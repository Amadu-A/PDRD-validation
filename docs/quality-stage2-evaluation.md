# Quality, этап 2: контрольное сравнение H01–H35

Это сравнение одного межстраничного маршрута и Finalization на одинаковых исходных данных. Это не полный повторный серверный анализ и не окончательная оценка точности. Ниже номера записей относятся к локальным результатам, а не к PDF-отчёту последнего job.

Условия: 31 страница исходного ИОС2.2, неизменный снимок 245 извлечённых фактов, нативные PDF-слова; одна `shared-vlm`, одинаковые seed/температура/бюджеты use case, три последовательных обращения для каждой версии. Поиск N/T/U/EQ в этой модельной сверке не выполнялся заново; отдельный программный N-проход использовал фиксированный локальный корпус без подтверждённых сведений о нормативном статусе.

Матрица помечена `needs_engineer_adjudication`. Приведённые доли — предварительные строгие показатели покрытия (Recall по прямым совпадениям), а не доказанная полнота экспертизы. Precision не измерен: отсутствие совпадения с кейсом не доказывает ложность замечания; нужны независимая разметка итогов и решение инженера по спорным кейсам. Частичные и тематические совпадения в строгий Recall/P0 Recall не включены.

Пустой GPU-порт, два повтора: f43639e — 6/6 итогов, a44d300 — 6/6, новая версия — 7/7. H09 в новой версии сохраняется программно даже без ответа. У второго PDF ИОС4.1.7 — прежний один вопрос во всех версиях, без новых генераций и без изменения его текста/оснований. Это проверка устойчивости; её нельзя выдавать за Recall действующей модели.

Старый счётчик `rejected_count=4` включает эти внутренние диагностические записи и сам по себе не означает четыре ложных замечания.
