## Границы результата

Проверки типов диаметров, карт, режимов, назначения свойств и единиц консервативны.
Не реализован универсальный математический интерпретатор естественного языка:
суммы таблиц и физическая совместимость требуют полных исходных данных и проверки модели.
Правила о полноте таблиц и материале клина добавлены в инженерный промпт и тесты
различимости свойств. Они не означают доказанную безошибочность VLM.

Счётчики running означают запросы, допущенные адаптером; provider_ms включает
сетевое время, внутреннюю очередь vLLM и генерацию. Это не чистое время GPU.
Внутреннюю очередь vLLM следует измерять его /metrics. Лимит и справедливость
действуют в одном процессе Analysis Service и не распределяют физические GPU
между всеми приложениями сервера. TP/DP/model/GPU не изменяются.

Точное кеширование осталось снаружи admission: тёплый cache hit не занимает слот.
Идентичность задания не входит в ключ кеша. После изменения промптов первый
прогон может быть холодным; сравнение скорости требует отдельного прогрева.
Дополнительные crops требуют времени, но не запускаются для чётких фактов.
E не включается. Страницы, требования ТЗ, источники и позиции не сокращаются ради скорости.

## Повторяемая приёмка

Локальный итог: полный Windows quality gate — 2415 Python-тестов прошли,
115 проверок реальной БД/runtime пропущены; все 354 frontend-теста прошли.
Ruff check/format и git diff --check прошли. Отдельная короткая приёмка —
52 теста за 3,66 секунды; дополнительные 18 проверок нового package-контракта
и изменённого Linux runner также прошли. Последняя корректировка распознавания
диаметров проверена 32 профильными тестами (0,15 секунды). Docker daemon локально недоступен,
поэтому сборка контейнеров и PostgreSQL round trip требуют серверного gate.

Сначала без GPU выполнить существующий `ops/check-quality.ps1` или
`bash ops/check-quality.sh`. Короткие новые тесты используют mock VLM, настоящий
файловый кеш, PIL и HTTP; не требуют сервера модели. PostgreSQL-проверка нового
progress хранится в существующем `test_database.py` и запускается в изолированном
integration окружении при PDRD_RUN_DATABASE_TESTS=1. Пропуск БД в локальном gate
не является подтверждением применения миграции.

После обновления кода применить миграцию Gateway `20261014_0009` и пересоздать
приложение существующим `bash scripts/up.sh`. В период обновления активных анализов
не должно быть. Импортировать и опубликовать все три файла
`n8n/workflows/analysis-v2-{pdf,cad,pdf-cad}.json`. Сервер и workflows используют
общий контракт cancelled; обновление только одного из них не завершает исправление.

Новая настройка .env.example: ANALYSIS_SERVICE_PIPELINE__MAX_GRAPHICAL_CROPS=2.
Можно явно задать 0 для сравнения без уточнения графики. .env автоматически
не изменяется. Перестройка индексов и смена VLM/GPU не требуются.

Для реальной оценки:

1. Сохранить опубликованный workflow и текущие настройки, SHA PDF и версии.
   Использовать исходный PDF без экспертных комментариев. Не передавать JSON
   benchmark в prompt и не анализировать PDF с человеческими аннотациями.
2. Повторить условия A и B: одинаковый доступный нормативный раздел, те же
   дополнительные режимы, без приложенного ТЗ. Сохранить исходный JSON отчёта.
3. Прогреть кеш одним завершённым прогоном и повторить один анализ. Затем запустить
   второй такой анализ параллельно из другого окна. Сохранить время первого и
   второго, счётчики waiting/running и все вызовы провайдера. Отдельно повторить
   холодные разные документы, чтобы cache hit не скрывал конкуренцию.
4. Для T-first отдельно использовать настоящее ТЗ и сверить полный ordered набор
   requirement_id каждой страницы. Мок не заменяет реальный набор требований.
5. По каждому H01–H35 инженер отмечает: совпадение смысла/частичное/пропуск;
   подтверждённое нарушение/конкретное подозрение/недостаточность данных;
   найденные N и их применимость; страницы и bbox источника, а не FreeText-аннотации.
6. Отдельно проверить новые обоснованные находки и прежние корректные находки.
   Увеличение количества замечаний не считается улучшением. Повторы считать только
   при совпадении объекта/области и основания; разные страницы evidence не удалять.
7. Отменить каждый этап, включая ожидание слота и середину T/N/finalization.
   Ожидать Respond Cancelled без красного HTTP-узла, без следующей VLM-порции и
   без частичного completed результата. Ошибки 422/503 должны остаться ошибками.

Ручная UI-проверка: без раздела кнопка отключена и объясняет причину при наведении;
выбор раздела разрешает запуск после подготовки ТЗ; снятие выбора либо удаление
раздела снова блокирует его. Закрытие modal и очистка ТЗ не снимают эту блокировку.
Прогресс показывает Understanding, отдельный T-first только с ТЗ, Check Norms и
Finalization; очередь GPU видна отдельно. Review, PZ, D/EQ, экспорт PDF и все
источники проверяются на тех же исходных страницах до и после изменения.
