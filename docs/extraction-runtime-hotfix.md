# Ошибка Document Extract PDF: права тома и адрес Spec

База: `feature/quality`, `ac2b3c3`. Проверка 17.11.2026.
Коммит и push выполняет владелец. Workflow, интерфейс, геометрия Review,
N-first, embedding и параметры VLM в этом пакете не меняются.

## Первопричины

1. `document-service` работает от UID/GID 1000, но новый named volume
   `/data/extraction-artifacts` был создан от root с правами 0755.
   После успешного ответа Docling сохранение в `docling/` вызывало
   `PermissionError: [Errno 13]`. `/health/ready` прежде не проверял запись.
   Это подтверждено серверным traceback, UID и владельцем тома.
2. Контейнерный URL Spec ошибочно указывал `8080`; действующий API и Compose
   соседнего проекта используют `8083`. Из-за отказа соединения включённый Spec
   переходил в native fallback. Оба выделенных ключа уже присутствуют, менять их
   для устранения этих двух причин не требуется.

## Исправления

- Runtime Dockerfile создаёт собственный каталог с владельцем `app` до `USER app`.
  Новый том наследует корректные права образа.
- Существующий том восстанавливается через штатный `scripts/up.sh` после сборки:
  одноразовый `chown 1000:1000` только его корня. Нет рекурсивного chown,
  `chmod 777`, удаления данных или запуска рабочего HTTP-процесса от root.
- DI передаёт readiness те же хранилища, которые используют Spec и Docling.
  Проверяются реальные создание файла, запись и fsync от рабочего пользователя.
  Probe не меняет готовые JSON/digest и не оставляет файлов.
- Extract проверяет хранилище до рендеринга и внешних вызовов. Поздний файловый
  отказ также возвращается как `503 extraction_storage_unavailable` с безопасным
  текстом. Он не маскируется пустыми строками или успешным native fallback.
  Повреждение digest и непредвиденные программные исключения не скрываются.
- Порт `8083` согласован в Settings, Compose, `.env.example` и документации.
- `check-stack.sh` проверяет health включённых интеграций и credential Spec через
  чтение отсутствующего UUID (404 после авторизации). Заданий не создаёт.
  Ключи не передаются аргументами процесса и не печатаются.
- При timeout общего startup теперь выводится и журнал Document Service.

## Реальные проверки

- Исходный PDF совпадает по SHA256 с локальным контрольным ИОС2.2:
  `76e3f20c20bd0ab570d04ee93916928c9a56d432045afb3ed5fc46470f49cdfa`.
- На действующем сервере адресно восстановлен владелец только собственного тома.
  Document пересоздан с тем же рабочим образом и исправленным URL Spec.
  Серверный Git и `.env` не изменялись; остальные сервисы не пересоздавались.
- После исправления прав прямое извлечение всех 31 страниц вернуло HTTP 200.
  Этот первый запрос ещё показал fallback Spec, что позволило обнаружить ошибку порта.
- После исправления порта Spec завершил задание
  `173c0ad0-6eb9-4a67-b73e-591cb846b8c0`, сохранил 53 строки и два предупреждения:
  20 строк на физической странице 26, 23 на 27 и 10 на 28. На странице 2
  отсутствует товарная спецификация; это отражено в предупреждении.
- Исправленный runtime-образ отдельно собран на сервере из текущих локальных
  файлов. Под UID 1000 проверены свежий том и непустой прежний root-owned том:
  EACCES воспроизводится до chown; после него оба хранилища сохраняют и читают
  по 100 строк с проверкой digest. Исходный контрольный файл не меняется.
  Удалены только два временных тома с индивидуальной тестовой меткой.
- На новом образе в отдельном HTTP-контейнере с реальным окружением Compose:
  readiness 200, извлечение 31/31 страниц, 53/53 строк, ПЗ 24 страницы.
  Время тёплого извлечения 7,92 с. Рабочий кэш подключался только для чтения
  и копировался в временный том; дополнительной генерации не требовалось.
  Контейнер и его временный том удалены. Это время извлечения, не всего анализа.
- Обновлённый `check-stack.sh` реально выполнен на сервере из отдельного
  временного файла: `STACK CHECK PASSED`, включая Spec/Docling.

Отдельная дублирующая сборка runtime на Windows Docker прервалась на скачивании
NumPy из `files.pythonhosted.org` с ReadTimeout. Полная сборка и runtime-проверки
проведены на сервере; сетевой timeout не подменён положительным результатом.

## Итог полного серверного запуска и качество

Задание завершилось `completed`, одна попытка, без error_code. Интервал создания —
завершения: **26 мин 28 с**; профиль `total_wall_ms=1588133.17`.
Все 31 страницы сохранены в API-ответе и прошли Understanding, Check Norms и
Finalization. В Understanding сохранились все 53 строки Spec (20/23/10 на 26/27/28).
Итог: 31 замечание и две диагностические гипотезы; длина массива findings — 33.
Гипотезы не учитываются как воспроизведённые инженерные замечания.

Скачивание через frontend proxy: HTTP 200, 4 678 907 байт, 9,99 с. В PDF 91 страница,
включая исходные 31 и полный отчёт/продолжения. Оригинальные области всех 31 страниц
проверены при 72 dpi без аннотаций: пиксельно идентичны. При включённых аннотациях
сохранены красные прямоугольники и линии (230 Square / 152 Line с красным цветом).
Отрендерены 8, 13, 16, 25, 26; страницы 8 и 25 дополнительно просмотрены визуально:
карточки справа, исходный чертёж не сдвинут относительно своей области.

Матрица: одноимённый JSON ИОС2.2 из доступного media-каталога, 59 включённых
аннотаций и одна исключённая `flag=false`. Ожидаемые замечания в конвейер не подавались.
После завершения выполнена явная смысловая оценка через существующий
`scripts/evaluate_human_remarks.py`: **13 matched / 1 partial / 45 not_matched,
22,03% полного воспроизведения**. Для каждого положительного решения проверены
реальный finding_id, цитата и требуемый физический лист. Это предварительная
оценка Codex, а не независимое инженерное подтверждение всех требований матрицы.
Повторные аннотации матрицы сохранены: два одинаковых вопроса на листе 15 ссылаются
на одно замечание; это не две независимо найденные ошибки.

Совпали: согласование состава гидрантов на 8, обоснование 100+100+50 м³ на 8/18,
годы СП на 9/10, обоснование 10 л/с и «водоотведение В2» на 13, 0,5205 против 0,205
на 15/30, вопросы к требуемым напорам В1/В2 на 16, неверная ссылка 2/3 на 20.
Гарантированные и требуемые напоры имеют разные роли: совпадение засчитано по
предметному вопросу обоснования, не по недоказанному требованию приравнять их.

Что осталось исправлять в качестве:

1. Различать календарную дату и позиционный тег по контексту/геометрии штампа:
   `p25-dpos-08-09-26` ошибочно принимает даты подписей за повторную позицию.
2. Проверять сопоставимость объектов и первичную цитату до вопроса о противоречии.
   Например, утверждение о двух вводах В2 требует проверки исходной текстовой
   привязки; вопрос о SDR разных втулок — идентичности типоразмера и условий.
3. Сохранять все целевые места одной претензии. Вопрос к запасу есть на 8/18,
   но требуемое место на 9 не воспроизведено; вопрос к диаметру есть на 17,
   а матрица требует его на 16. Простое совпадение системы или справочной страницы
   не засчитывается как воспроизведение на нужном листе.
4. Восстановить проверки нормативной применимости, ссылки на серию основания,
   длины 147/150, шифров и сквозной нумерации, содержимого/названий таблиц.
   Увеличение количества свободно сгенерированных замечаний этого не решает.
5. Провести аудит N-first и его счётчиков. Ответ сообщает selected=10200,
   supported=13, unsupported=10187, evaluated=0, confirmed violations=0.
   Эти значения нельзя представлять как доказанную проверку всех 10 тысяч атомов.
6. Уменьшить доказательственные пакеты без потерь источников. Check Norms:
   789,10 с wall, 1 193 156 входных токенов, 31 вызов, ноль retry и cache hit;
   суммарное ожидание слота по параллельным операциям — 2 132,38 с (не wall).
   Understanding — 459,61 с wall; Finalization — 64,69 с wall.
   Новый готовый кэш Spec ускорил извлечение, но не решил перегрузку контекста N-first.

Подробные решения: `semantic-decisions.json`, `semantic-assessment.json`; реальный
API-ответ: `result.json`; PDF и рендеры — в том же игнорируемом каталоге логов.
С исходными бинарниками, ключами и гостевым токеном они в коммит не включаются.
Цели **3–5 минут** и **50–70%** этим исправлением не достигнуты. Исправление
восстанавливает работу и даёт реальный контрольный результат для следующих изменений;
модельные правила в этот инфраструктурный пакет не добавлялись без отдельной проверки.

## Поставка одним коммитом

Windows, из корня. Приватные ключи остаются в `.env`:

```powershell
.\ops\check-quality.ps1
if ($LASTEXITCODE -ne 0) { throw 'Quality gate не прошёл' }
$files = Get-Content docs/extraction-runtime-hotfix-files.txt | Where-Object { $_ -and -not $_.StartsWith('#') }
git add -- $files
if ($LASTEXITCODE -ne 0) { throw 'Ошибка добавления файлов' }
git diff --cached --check
if ($LASTEXITCODE -ne 0) { throw 'Ошибка staged diff' }
git diff --cached --stat
git commit -m "fix: восстановить runtime извлечения PDF и проверку Spec/Docling"
if ($LASTEXITCODE -ne 0) { throw 'Коммит не создан' }
git push https://github.com/Amadu-A/PDRD-validation.git HEAD:feature/quality
if ($LASTEXITCODE -ne 0) { throw 'Публичный push не выполнен' }
git push https://github.com/neo-term-it/PDRD-validation.git HEAD:feature/quality
if ($LASTEXITCODE -ne 0) { throw 'Приватный push не выполнен' }
```

Linux, штатный сценарий применяет исправление и к прежнему тому:

```bash
cd ~/projects/PDRD-validation
mkdir -p .codex-test-temp/extraction-runtime-delivery
git pull --ff-only https://github.com/neo-term-it/PDRD-validation.git feature/quality || exit 1
bash ops/check-quality.sh > .codex-test-temp/extraction-runtime-delivery/quality.log 2>&1 || {
  tail -n 100 .codex-test-temp/extraction-runtime-delivery/quality.log
  exit 1
}
bash scripts/up.sh > .codex-test-temp/extraction-runtime-delivery/up.log 2>&1 || {
  tail -n 100 .codex-test-temp/extraction-runtime-delivery/up.log
  exit 1
}
bash scripts/check-stack.sh || exit 1
```

Повторная публикация n8n не нужна: workflow в этом пакете не менялся.
Миграция, переиндексация, очистка Qdrant или удаление томов не требуются.

## Ручная проверка

Открыть `http://192.168.55.3:8080/`, выбрать ИОС2 и нормативные документы,
загрузить прежний PDF. Анализ с D/ПЗ/EQ должен пройти Document Extract PDF без 500.
После завершения скачать PDF и проверить красные рамки, линии и правую колонку.
Проверить сохранение/перезагрузку ручной геометрии в авторизованном Review,
утверждение/редактирование и удаление Gold без причины. В этом пакете frontend
и Review не менялись. Рабочий Chrome не использовался и не изменялся.

Откат: revert одного коммита и обычный up. Возвращать том root-владельцу не нужно;
это снова сломает сохранение. Откат кода с прежним URL 8080 также вернёт fallback
Spec, поэтому для такого отката нужно сохранить правильный URL 8083 в private override.
