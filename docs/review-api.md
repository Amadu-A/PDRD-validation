# Этап 5: серверный Human Review

## Назначение и границы

Gateway соединяет существующий анализ и отдельный Experience Service.
Experience хранит все замечания, решения, исходные/исправленные тексты,
операционную геометрию, ревизии и неизменяемый аудит в схеме `experience`
проектного PostgreSQL. Изображения целых листов в Review не дублируются.

Это операционное хранилище, а не завершённый каталог Experience. Crop,
CRUD/экспорт примеров и индексация относятся к следующим этапам.
`edited + rejected` сохраняет обе формулировки и остаётся
`needs_adjudication` при отборе примеров. Автоматическое обучение выключено.

## Модули и ответственность

| Модуль | Ответственность |
| --- | --- |
| Gateway `application/ports/review.py` | Контекст инженера, задание, операция, политика доступа, порт Experience |
| Gateway `ManageReview` | Проверка доступа при каждой операции и вызов сервиса |
| Gateway `GetReviewSource` | Действующее задание, серверный PDF, результат и визуализация |
| Gateway `infrastructure/review.py` | Временный серверный оператор и закрытый HTTP-клиент |
| Experience `GatewayAnalysisSource` | Чтение артефактов через закрытый маршрут Gateway |
| Experience `VerifiedCompletedAnalysisReader` | Проверка задания, документа, исходного SHA-256, листов и оригиналов |
| Experience `OpenReview` / `ChangeReview` | Существующие доменные операции и атомарное сохранение через порт |
| Frontend `review/api.js` | Сетевой контракт, без ключей и идентичности инженера |
| Frontend `review/commands.js` / `sync.js` | Преобразование изменений, последовательная очередь и CAS |
| Frontend `review/persistence.js` | Состояния загрузки/сохранения и соединение DOM с очередью |
| Frontend `analysis/restore.js` | Восстановление завершённого отчёта по `job_id` URL |
| Frontend `review/tooltips.js` | Полный ответ за пределами обрезаемой карточки |

## HTTP-контракт

| Метод и маршрут Gateway | Назначение |
| --- | --- |
| `GET /api/v1/review/config` | Доступность серверного режима на текущем фронте |
| `POST /api/v1/analyses/{job_id}/review/open` | Первоначальное открытие либо восстановление |
| `GET /api/v1/analyses/{job_id}/review` | Текущая сохранённая редакция |
| `POST /api/v1/analyses/{job_id}/review/commands` | Одна команда с `expected_revision` |

Команды: `add`, `edit`, `decide`, `reset`, `geometry`, `approve`.
`approve` подготовлен для следующего этапа; итоговый PDF пока не формируется.
Запрещены неизвестные поля, `actor`, оригиналы, теги и клиентская подмена
идентичности документа. Сервер повторно проверяет UUID, физический лист,
области `0..1000`, длину текста и источники. Контракт обеих HTTP-границ
проверяется архитектурным тестом без взаимных импортов сервисов.

Незавершённое задание и конфликт ревизии возвращают `409`, неизвестное —
`404`, неправильная команда — `422`, недоступный серверный источник — `503`.
Повторное открытие не заменяет исходные тексты, в том числе при конкуренции.

## Геометрия и Experience

`proposed_regions` — неизменяемые предложения из серверной визуализации.
`display_regions` — операционные правки инженера, а `callout_box` — размещение
текста. Браузерные координаты не становятся подтверждёнными областями VLM.
Подтверждения VLM продолжают жить в отдельном серверном контуре
`ConfirmArea`/`RevokeArea` с собственным аудитом. Публичной команды для
автоматического подтверждения областью браузера нет.

Правка текста или геометрии инвалидирует подпись прежнего подтверждения,
решение и утверждение Review. Возврат старой области через Undo не оживляет
устаревшее подтверждение. Замечание без области сохраняется и рассматривается,
но ему не придумываются рамка/линия и обучающий crop.

Gold сохраняет обе области. Undo создания в серверном режиме записывает
отклонение, сохраняя аудит. В локальном режиме отменяется локальное добавление.
Тег Gold не меняется после исправлений. Исправленная VLM остаётся Edited.

## Контекст и закрытое окружение

Полноценной системы пользователей нет. `ReviewContextProvider` выдаёт
серверный `actor`, `job_id`, операцию. `ReviewAccessPolicy` — место будущей
проверки прав. Сейчас `ControlledReviewContext` использует явно настроенного
оператора; это не доказательство личности и не разделение владельцев заданий.
Режим запрещён при `API_GATEWAY_ENVIRONMENT=prod`.

До авторизации работает отдельный `review-frontend` на **127.0.0.1:8081**.
Доступ — локально или через SSH. Основной frontend на 8080 получает пустой
служебный ключ и показывает локальный предпросмотр. Даже переданный
браузером одноимённый заголовок nginx заменяет серверным значением.

Первый ключ защищает канал приватного nginx → Gateway. Второй, отличающийся,
защищает Gateway ↔ Experience. Ни один ключ не отправляется в JavaScript,
HTML или ответы. Проверяются origin и cross-site запросы. Experience не
имеет опубликованных портов и не подключается к `ai-shared`.

Все ключи и включение — в приватном `.env`. `ops/configure-review.py`
явно подготавливает этот режим, не выводит ключи, сохраняет старые настройки
и не меняет ключи при повторном запуске. Не публиковать этот фронт на LAN.

## Сохранение и перезагрузка

Редактирование заблокировано до получения серверного снимка. Команды идут
по очереди с ревизией последнего ответа. Сохранение показывается отдельно
от решения по замечанию. Изменения карточек синхронизируются с полным списком.

При сетевой ошибке или `409` локальная очередь остаётся на странице,
редактирование блокируется, автоматического повтора нет. Можно повторить
сетевую ошибку с той же CAS-ревизией. Если ответ потерян после commit,
повторный запрос получит конфликт и не создаст дубликат.

Кнопка загрузки серверной версии явно сбрасывает несохранённое состояние.
Перезагрузка использует `job_id` URL, восстанавливает существующий результат
и Review, не запускает VLM заново. Устаревший ответ восстановления не
подменяет новое задание. При незавершённой очереди браузер предупреждает
перед закрытием страницы. Новый анализ не запускается до опустошения очереди
либо явной загрузки серверной версии со сбросом несохранённых изменений.

## Проверки и эксплуатация

Общий quality gate включает JS, unit, функциональные HTTP-сценарии двух
сервисов, регрессионные и архитектурные проверки. Изолированный PostgreSQL
проверяет миграции, конкуренцию, JSONB, геометрию и Undo. На этой Windows
Docker daemon не запущен; SQL-прогон выполняется командами ниже на Linux.

`ManageReview.execute` измеряет всю операцию декоратором
`log_execution_time(operation="review_request")`: `operation_timing`,
`duration_ms`, `status`. Тексты, ключи и аргументы не журналируются;
повторный traceback не создаётся. Docker `local` ограничивает журналы.

После общих и изолированных тестов:

```bash
python3 ops/configure-review.py --actor engineer:i.mein
docker compose --profile review config --quiet
docker compose --profile review build experience-service experience-migrate review-frontend api-gateway frontend
docker compose --profile review run --rm --no-deps -T experience-migrate </dev/null
docker compose --profile review up -d --no-deps --force-recreate --wait experience-service
docker compose --profile review up -d --no-deps --force-recreate --wait api-gateway frontend review-frontend
curl -fsS http://127.0.0.1:8080/api/v1/review/config
curl -fsS http://127.0.0.1:8081/api/v1/review/config
```

Ожидается соответственно `enabled: false` и `enabled: true`. Миграции
добавляют только схему Experience; существующие volumes не удаляются.
Новой DDL-миграции для `display_regions` нет: снимки/аудит используют JSONB.
Отсутствующее поле в старом снимке читается как `None`.

На Windows в отдельном терминале:

```powershell
ssh -N -L 8081:127.0.0.1:8081 main@192.168.55.3
```

Открыть `http://127.0.0.1:8081`. Для существующего отчёта использовать
`http://127.0.0.1:8081/?job_id=<UUID задания>`.
Проверить принятие, исправление, отклонение и Undo, создание/изменение Gold,
перезагрузку, сохранённый полный текст и конфликт второй вкладки.

Отключение режима: `API_GATEWAY_REVIEW__ENABLED=false` в приватном `.env`,
пересоздать Gateway, остановить `review-frontend`. Сохранённые Review не удалять.
n8n workflows на этом этапе не меняются.
