# Проверка оборудования по документации производителя

## Включение

На форме PDF два переключателя. «Искать документацию на оборудование в интернете» включает EQ независимо от D. «Разрешить неподтверждённые
источники для этого задания» доступен только вместе с EQ и не переносится
в следующую заявку. При выключенном EQ ветвь поиска, EQ embeddings и
дополнительные поля Understanding не запускаются.

Для сервисного взаимодействия задайте `PDRD_EQUIPMENT_INTERNAL_KEY` в
приватном `.env` на сервере. Остальные значения берутся из
`.env.example` и типизированных настроек. Один и тот же ключ используют
API Gateway и Equipment Search Service. SearXNG доступен только во
внутренней сети Compose.

## Маршрут и источники

После Understanding уникальные пары «производитель, модель, исполнение»
попадают в Equipment Search. Неуверенная идентификация остаётся
`needs_review` и не вызывает внешний поиск. Сначала используется
локальный snapshot. При его отсутствии сервис ищет через локальный
SearXNG, сначала на доверенных доменах производителя, затем общим
запросом. Во внешний запрос входят только маркировка и нейтральные
слова о документации; параметры проекта, PDF и внутренние ID не
передаются.

Новый hostname регистрируется как `pending`. По умолчанию его документ
не загружается. `blocked` запрещён и при разрешении неподтверждённых
источников. Доверие привязано к точному hostname и производителю.
Администратор с `equipment_sources.manage` видит источники,
историю решений и может менять статус в личном кабинете.

Безопасный загрузчик проверяет схему URL, DNS/IP и каждый redirect,
закрепляет проверенный публичный IP для подключения, проверяет TLS,
ограничивает размер и принимает только фактический PDF/HTML. HTML
обрабатывается как текст. Сохранённые байты доступны по EQ source ID;
при чтении повторно проверяется SHA-256.

Document Service извлекает текст страниц. Knowledge Service строит
ограниченный локальный векторный индекс нового snapshot для ранжирования
релевантных страниц, затем детерминированно извлекает EQ Facts. Версии
схемы и извлекателя входят в ключ кэша. Повторный анализ того же
snapshot читает EQ Facts без новой индексации. Точная строка модели
или явно подписанная колонка таблицы может дать сравнимый факт.
Сбитая таблица, непроверенное исполнение, особые условия и конфликт
сохранённых ревизий остаются на проверку инженера.

Analysis Service сопоставляет только совместимые свойство, роль
входа/выхода, AC/DC, фазность, режим, исполнение и физические единицы.
Кандидаты присоединяются к общим замечаниям перед нормативным
обогащением и Finalization. EQ source ID, ревизия, страница, фрагмент,
URL, доверенность и значения проходят в отчёт, Review и PDF.
При отказе EQ ветви основной анализ сохраняет результат и предупреждение.

## Проверка после развёртывания

1. Без EQ повторите привычный PDF: состав замечаний и число EQ-вызовов
   должны оставаться прежними, блок EQ не показывается.
2. Включите EQ при D=false и D=true. В ходе задания видны события
   поиска; после переподключения они продолжаются с Last-Event-ID.
3. На модели с доверенным документом проверьте найденный snapshot,
   исходные значения, страницу производителя и ссылку на сохранённую
   копию. Корректное значение не создаёт замечание.
4. Для неизвестного домена проверьте `pending` в личном кабинете;
   после подтверждения повторите анализ. `blocked` не применяется
   даже при втором переключателе.
5. Откройте историю, Review и итоговый PDF. EQ источник должен
   оставаться отдельным от N/T/U/D/E.
6. Отмените задание во время поиска: новых запросов и загрузок быть
   не должно. Повторите с недоступным SearXNG: основной результат
   должен завершиться с предупреждением.

## Адресный VLM и бюджеты

Для PDF без текстового слоя проверяются максимум две выбранные физические
страницы. Document Service растеризует только запрошенную страницу;
Analysis Service проверяет точную маркировку и читает до восьми строк.
Соседняя модель, исполнение или невалидный ответ отклоняются.
Визуальные строки нормализуются Knowledge и остаются `needs_review`.
Транскрипция сохраняется отдельно от байтов snapshot и переиспользуется
после повторного анализа без нового VLM.

Лимиты из `.env.example` общие для всех моделей задания: 6 запросов,
3 загрузки, 2 адресных VLM вызова, 12 моделей, 180 секунд.
На один запрос допускается 8 URL, на документ — 12 МБ и 40 страниц.
Одновременно работают два поиска. Все VLM этапы Analysis Service
используют один limiter с `ANALYSIS_SERVICE_PIPELINE__VLM_STAGE_CONCURRENCY`.
Сборка Compose запускает один процесс Analysis Service; при добавлении
реплик потребуется распределённый limiter. Scheduling физических GPU
остаётся ответственностью shared vLLM.

Исчерпание бюджета сохраняет `incomplete` и причину. Отмена прекращает
новые операции; сетевой поток проверяет её перед следующим redirect и
чтением. После рестарта незавершённые задания закрываются как `incomplete`
с событием в истории. Основной анализ сохраняет доступные результаты.


## Архитектура и наблюдаемость

Оркестрация извлечения и кэша EQ Facts находится в application Knowledge.
PostgreSQL реализует только порт чтения/сохранения; контейнер связывает
его с application индексом и существующими embedding/vector адаптерами.
Архитектурный тест контролирует и новый Equipment Search Service.
Ключевые операции поиска, запуска задания, извлечения EQ Facts и
адресного VLM измеряются reusable декоратором: `event=operation_timing`,
`operation`, `duration_ms`, `status`. Аргументы, документы и ключи в
эти события не попадают.

Для каждой модели сохраняются длительность, число поисковых запросов,
загрузок, VLM вызовов, VLM cache hits и входных/выходных токенов.
Поля VLM метрик зависят от ответа shared vLLM; отсутствие usage нельзя
считать доказательством нулевого расхода. Инвентарь и диагностика EQ
сохраняются даже при отсутствии сравнимых параметров.

Настройки контейнера SearXNG сверяются с
[официальной документацией](https://docs.searxng.org/admin/installation-docker).
Смена версии образа требует отдельной проверки поискового JSON API.

## Автоматические проверки

На Windows из корня репозитория:

```powershell
New-Item -ItemType Directory -Force .codex-test-temp/logs | Out-Null
powershell -NoProfile -ExecutionPolicy Bypass -File ops/check-quality.ps1 -Fix *> .codex-test-temp/logs/quality-windows.log
if ($LASTEXITCODE -ne 0) { throw "Ошибка проверки: см. quality-windows.log" }
```

Скрипт проверяет зависимости, Ruff lint/format, весь pytest, все frontend
тесты и `git diff --check`. Пропущенные проверки настоящей инфраструктуры
выполняются на Linux с Docker через `bash ops/check-quality.sh`:
общий набор и шесть отдельных стеков Gateway, Knowledge, Experience,
User, Auth, Equipment Search.

Изолированный стек Equipment использует собственный PostgreSQL в tmpfs,
без опубликованных портов и внешних сетей. Он применяет миграции до
запуска всех тестов сервиса. Knowledge запускает весь integration каталог,
включая сохранение/повторное чтение EQ Facts. Нельзя включать DB тесты
на рабочей базе: новые EQ тесты дополнительно проверяют имя БД и host.

## Обновление сервера

Сначала просмотрите diff и выполните Windows проверки. Коммит и отправку
в оба настроенных push URL выполняет разработчик. Агент их не выполняет.
В каталоге репозитория на сервере получите ветку из приватного репозитория:

```bash
set -euo pipefail
git fetch https://github.com/neo-term-it/PDRD-validation.git feature/searXNG
if git show-ref --verify --quiet refs/heads/feature/searXNG; then
    git switch feature/searXNG
else
    git switch -c feature/searXNG FETCH_HEAD
fi
git pull --ff-only https://github.com/neo-term-it/PDRD-validation.git feature/searXNG
mkdir -p .codex-test-temp/logs
bash ops/check-quality.sh > .codex-test-temp/logs/quality-server.log 2>&1
bash scripts/up.sh > .codex-test-temp/logs/rebuild-server.log 2>&1
bash scripts/check-stack.sh > .codex-test-temp/logs/readiness-server.log 2>&1
```

Перед первым запуском добавьте только `PDRD_EQUIPMENT_INTERNAL_KEY`
(случайный секрет не менее 32 символов) в приватный серверный `.env`.
Остальные новые параметры остаются в `.env.example`. `scripts/up.sh`
валидирует ключ, пересобирает стек и запускает миграции Equipment
через Compose dependency. Проверка стека контролирует состояние
SearXNG, готовность Equipment и текущую версию миграций.

В shared n8n обновите существующий PDF workflow содержимым
`n8n/workflows/analysis-v2-pdf.json` и опубликуйте его. Пересборка контейнеров
не обновляет опубликованный workflow в shared n8n.

## Приёмка на контрольных PDF и GPU

Автоматические проверки с fake HTTP/VLM не заменяют измерение на реальном
shared vLLM. Для приёмки нужны контрольные PDF и согласованный инженером
ожидаемый результат. Проверьте как минимум корректный параметр, заведомое
расхождение, соседнюю модель, неоднозначное исполнение, семейную таблицу,
скан и конфликт ревизий.

На одном и том же документе, версии модели и workflow выполните:

| Режим | Условия | Ожидаемое поведение |
| --- | --- | --- |
| EQ выключен | Прежние N/T/U/D/E настройки | 0 EQ HTTP/embedding/VLM вызовов; прежний результат |
| EQ включён, холодный документ | Новый snapshot без EQ Facts | Ограниченные запросы/загрузки/индексация; нет второго полного VLM прохода проекта |
| EQ включён, повторный документ | Те же байты snapshot и версии извлекателя | Локальный документ и EQ Facts; без повторных поиска, загрузки, индексации и VLM |

Для каждого режима сохраните ID задания, hash контрольного PDF и
snapshot, D/E настройки, версию модели/workflow/извлекателя, время полного
анализа и EQ ветви, числа HTTP/embedding/VLM вызовов, входных/выходных
токенов, пиковую VRAM, GPU utilization и задержки shared vLLM. EQ метрики
берите из результата/истории; общие GPU показатели — из наблюдаемости
shared infrastructure. Выполните по несколько повторов и сравните
медиану и худшее значение. Порог допустимого прироста согласуется по
контрольному набору, его нельзя объявить пройденным по локальным fake тестам.

Проверьте отмену в очереди и во время сетевой/GPU операции, восстановление
SSE после обновления страницы, закрытие прерванных заданий после рестарта,
fail-open при отказе SearXNG/Knowledge, ограничение общей параллельности VLM
и сохранение EQ provenance после Review, Gold export и скачивания PDF.
