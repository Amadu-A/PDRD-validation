# N-first A+–E: реализация, проверка и ограничения приёмки

Изменение готовится одним набором поверх `feature/quality`, HEAD `199697c`.
Коммит, push и поставку выполняет разработчик. Изменение не включает миграцию БД,
перенастройку shared runtime, параметров VLM или embedding. Автоматической
переиндексации существующих нормативов нет.

## Отказ frontend

20.10.2026 прямые HTTP-запросы к frontend сервера подтвердили 403 для
`js/features/analysis/visualization.js`, `js/features/review/controller.js` и
`css/blocks/review-resize.css`; существующий модуль auth/session.js отвечал 200.
Nginx не содержит отдельных запретов для этих путей. Недоступный импорт прерывает
граф ES-модулей до подключения обработчиков входа/регистрации.

Наиболее вероятная первопричина — недоступные nginx worker права новых файлов.
Проверить `stat` на сервере из этой сессии не удалось: SSH отклонил ключ.
Dockerfile теперь задаёт файлам 644, каталогам 755 и проверяет чтение от имени
nginx при сборке. up.sh пересобирает также отдельно поднятый review-frontend,
даже когда профиль review отсутствует в .env; одного force-recreate старого
образа для обновления файлов недостаточно. Права 777 и снятие серверной авторизации не используются.
`check-stack.sh` проверяет реальные URL критических модулей и CSS обычного
frontend и активного review-frontend. Три сценария «HTML 200, отдельный asset
403» завершают readiness ошибкой. Геометрия и обработчики Review не переписаны.

## B: независимый проход

Порт чтения каталога реализован HTTP-адаптером существующего Knowledge API.
Он проверяет принадлежность разделу, полную пагинацию, счётчик и уникальность
атомов, SHA и неизменность поколения. Частичный/повреждённый корпус не становится
полным. Ожидаемые сетевые ошибки сохраняются как source_missing; непредвиденные
программные исключения не маскируются пустыми результатами.

Для PDF весь выбранный корпус читается один раз на пакет. Проверки используют
реестр фактов всех переданных физических страниц. Предварительные findings
не входят во вход независимого прохода. Application получает существующий
нейтральный DocumentPage; HTTP DTO преобразуются только в transport.
Вычисление корпуса вынесено из ASGI event loop и не занимает GPU-слот;
соседние запросы и отмена продолжают обслуживаться.
Сохраняются причины отбора/исключения,
manifest поколений и дата оценки. При отсутствии класса в распознанных материалах
исключение видно в selection; оно не является юридическим выводом о неприменимости.
При неизвестном классе общая норма сохраняется для диагностики.

Поддержаны однозначные числовые ограничения, условные ограничения, числовые и
классификационные предпосылки, явно подписанные двухколоночные таблицы, буквальные
формулы с расшифровкой переменных и единицами, явное наличие/отсутствие требуемого
компонента, конкретные вопросы о связи принятого параметра с расчётом.

Направление табличного ограничения должно быть напечатано в источнике.
Формулы вычисляются безопасными интервальными операциями; пересечение нуля
в знаменателе оставляет проверку неподдержанной. Сопоставление выполняется
в рамках одного объекта и условий. Отсутствие прочитанного компонента не равно
его отсутствию. Исключения и нормативные зависимости без доказанного разрешения
не обходятся. Эти ограничения исключают универсальную автоматическую проверку
произвольной нормы: поддерживаемые формы перечислены, прочие сохраняются явно.

Старый Check Norms, T/U, D/E/EQ и свободное обнаружение сохранены.
Флаг `ANALYSIS_SERVICE_NORMATIVE_PLAN__ENABLED=false` даёт исходный маршрут;
`true` добавляет независимый проход. Новые VLM/embedding-вызовы для него не нужны.
Программное доказательство повторно вычисляется в существующей Finalization.

## C: сквозное N-основание

`NormativeSource.atomic_requirement` сохраняет исходные requirement_id/point_id,
редакцию, пункт/подпункт, physical page, SHA, generation, полную цитату,
source_fragments, условия, исключения, зависимости и датированный журнал статуса.
Контракт проходит Analysis API, Finalization, серверное открытие Review,
JSONB codec, повторное открытие и manifest Reviewed PDF. Существующие Review
снимки не переписываются: недостающие N-данные не восстанавливаются задним числом.

Полный отчёт frontend показывает атомарный адрес и статус в существующем списке
источников. Карточки и геометрия не меняются. Автоматический и Reviewed PDF
содержат N-реквизиты и native URI-ссылку на физическую страницу оригинального
норматива. Используется только настроенный `API_GATEWAY_IDENTITY_PROXY__PUBLIC_ORIGIN`;
при пустом origin текст остаётся, адрес не выдумывается. Кеш производного
автоматического PDF обновлён до annotated-v9; VLM-кеш не сбрасывается.

Смена public origin после выпуска требует инвалидировать только производный
автоматический PDF. Reviewed PDF учитывает origin в ключе кеша.

## D: независимые инженерные претензии

Убрано влияние технического program-check hash на идентичность одной претензии
о назначении системы. Происхождение программного доказательства остаётся в
истории. Одна система с ошибкой маркировки и отдельным вопросом обоснования
сохраняет две претензии. Существующее объединение сохраняет страницы, области,
источники и историю; визуальная группировка не возвращается.

Нативный парсер читает явно названную общую протяжённость сети. Длины отдельных
участков L и DN/Ду не выдаются за итог. При двух сопоставимых итогах существующий
межстраничный механизм самостоятельно создаёт кандидата. В продуктивных правилах
нет ID, чисел или ожидаемых ответов матрицы H01–H35.

Сохранение подготовленных H09/H10/H16/H24 проверяется существующим retention
набором; он не измеряет самостоятельное обнаружение. Реальный H10 остаётся
неподтверждённым: матрица сама требует уточнить, что означает «в спецификации 150».
Подменять длину диаметром для получения совпадения запрещено.

## E: выполненное сравнение и границы выводов

Контролируемый offline replay использовал один исходный PDF (31 страница,
SHA-256 `76e3f20c20bd0ab570d04ee93916928c9a56d432045afb3ed5fc46470f49cdfa`),
245 сохранённых фактов и четыре настоящих нормативных PDF. Сравнивался исходный
код HEAD с текущим; это повтор обработки фактов, не новый запуск модели.

Шесть прежних выводов сохранены без изменения текста, статуса и рекомендации;
пять полных payload совпадают, шестой дополнен одним источником D без потери
прежних источников. Это меняет его автоматический ID в новом запуске, но не
переписывает существующие Review-снимки. Сохранены: внутренняя ссылка на баланс, вопросы по двум
защищаемым объектам, основанию пожарного расхода, гидравлическому выбору и запасу.
При повторе независимого нормативного прохода сохраняется одинаковый хеш всего
результата и диагностики. Проход полного локального корпуса занимает примерно
4,4 секунды (оба повтора); до устранения повторной обработки неподдержанных
атомов занимал 50 секунд. Все 5796 атомов учтены в selection, 5585 отобраны,
211 исключены с причиной. Дополнительные проверки внутри атома считаются отдельно.
Подтверждённых N-нарушений — 0: статусы не подтверждены.

Прямые смысловые совпадения H01–H35 нового серверного прогона **не измерены**.
Новые кандидаты и отсутствие потерь не означают роста recall/precision.
Два контрольных job_id на доступном frontend API ответили 404; исходные API JSON
и исходная геометрия этих прогонов здесь не получены. Присланный частичный
PDF-derived JSON ими не заменялся. Сравнение frontend скриншотов run8/run9 с новым
серверным результатом не выполнено. Контрольный рендер новых PDF-ссылок проверен
визуально и по границам текста/ссылок; он не является этим сравнением.

20.10.2026 read-only API сервера показал: у 11 документов ИОС2 нет активных
атомарных поколений, журнал status_evidence пуст. Состояние индекса чанков
не заменяет атомарное поколение. Нельзя заявлять приёмку независимого N-first
на реальном сервере до подготовки каталога и повторного анализа.

## Штатная поставка и приёмка

1. Windows: `powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\check-quality.ps1`.
2. Просмотреть полный diff и список файлов, подготовить один пользовательский коммит,
   отправить ветку в оба настроенных репозитория.
3. Linux: `git pull --ff-only origin feature/quality`, затем
   `bash ops/check-quality.sh && bash scripts/up.sh && bash scripts/check-stack.sh`.
   up.sh пересобирает образы, выполняет штатные миграции и readiness.
4. Импортировать, сохранить и опубликовать **все три** изменённых V2 workflow:
   analysis-v2-pdf.json, analysis-v2-cad.json и analysis-v2-pdf-cad.json.
   Для одной починки 403 перепубликация не нужна; для нового N-first необходима.
5. По инструкции этапа A просмотреть состояние/исходники выбранных нормативов,
   затем явно запустить requirements/index. Не подменять это индексацией чанков.
   Нормативный статус подтверждает уполномоченный инженер существующим API журнала,
   с источником, областью пунктов, редакцией и датой. Реальный статус не создаётся
   из учебных fixtures, READY или имени PDF.
6. Для B-сравнения включить ANALYSIS_SERVICE_NORMATIVE_PLAN__ENABLED=true в .env,
   штатно перезапустить up.sh. Зафиксировать source SHA, поколения, дату статуса,
   версии workflow, настройки и кеш; сопоставить исходный запуск, новый и повтор.
7. Проверить Network: JS/CSS 200, отсутствие ошибок импорта; открытие входа и
   регистрации, действительный вход по HTTPS, выбор раздела/файла.
8. Проверить отдельные карточки; в Review изменить текст, добавить/удалить область,
   изменить размер/положение рамки и карточки, подтвердить/отклонить, сохранить,
   обновить страницу. Соседние findings должны остаться независимыми.
9. Скачать оба PDF, проверить номера, страницы, ручную геометрию и переходы N-ссылок.
   Повторить проблемный документ до completed и оценить H01–H35 по смыслу,
   отдельно отмечая вопросы, нормативное подтверждение, дубликаты и точность места.

Локальный Windows gate не подтверждает Linux/Docker, PostgreSQL/Qdrant,
корпоративный DNS/VPN и реальный опубликованный n8n. В этой сессии Docker daemon
недоступен, SSH-ключ сервер не принял. Серверные quality/readiness и модельный E2E
нового кода остаются действиями поставки; выводы и пути у пользователя не запрашиваются.


## Результаты локальных проверок итогового набора

- Windows `ops/check-quality.ps1`: **3053 passed, 118 skipped**, все **397**
  frontend-тестов прошли; pip check, Ruff check/format и git diff --check без ошибок.
- Независимый проход и пакетные HTTP-сценарии: **38 passed за 3,12 с**.
  Здесь проверяются 31 физическая страница без предварительных модельных findings,
  сохранение N-основания через Finalization, полный корпус из 6000 учебных атомов,
  отзывчивость соседнего async-задания, неизвестные/повреждённые источники,
  классификация, формулы, таблицы, роли параметров и исключения.
- Контракты сборки/frontend/readiness/startup: **22 passed за 0,19 с**.
  Это проверка контрактов, не запуск образа Docker на этом компьютере.
- Review → JSONB codec → повторное открытие → Reviewed PDF проверены настоящими
  ASGI-маршрутами и PDF renderer с изолированным хранилищем. Реальные PostgreSQL
  проверки входят в пропущенные интеграции и должны пройти Linux quality gate.
- Рендер контрольного PDF просмотрен: русский статус, переносы и native URI
  корректны, текст/ссылки внутри страницы, растр исходной страницы не изменён.

Учебные положительные N-примеры доказывают работу механизма, но не юридическую
актуальность реальных СП и не самостоятельное обнаружение экспертных H-кейсов
на новом серверном прогоне. Соответствующие ограничения приёмки остаются выше.
