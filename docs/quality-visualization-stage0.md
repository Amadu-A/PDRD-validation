# Quality: раздельные замечания и геометрия, этап 0

Рабочая ветка: `feature/quality`. Исходный HEAD: `7c3881ff59437d3cc54bc6028d0d3562937488b7`.
Изменения подготовлены локально, без commit/push. N-first и последующие этапы этого ТЗ не изменяются.

## Причины и исправления

1. Frontend объединял находки по объекту и близости рамок в общий callout. Теперь каждый `finding_id` получает собственную карточку, номер, рамки, соединители и Review-действия. Общая область у двух находок сохраняет две независимые связи.
2. Повторяющиеся координаты рисовались несколько раз. Отображение и PDF удаляют только точные повторы внутри одной находки. Исходные объекты с источниками, текстами, страницами и provenance не изменяются. Разнесённые области не заменяются общим прямоугольником.
3. Пустая геометрия дополнительного доказательства могла вытеснить сохранённые основные VLM-рамки. Основная страница получает собственные исходные области вместе с дополнительными доказательствами; вторичная страница не наследует основные координаты. Дробные координаты сохраняются.
4. Обработчики визуализации и открытия Review усекали список до четырёх областей. Усечение удалено. Операционная геометрия ограничена существующим межсервисным пределом 9600 областей; это защитный лимит, а не способ ограничения исходных доказательств.
5. Review запрещал менять число рамок. Разрешены добавление и удаление областей существующей VLM-находки, включая переходы `0 → несколько → 0`. Исходные `proposed_regions` остаются неизменными; правки записываются в `display_regions` с CAS и аудитом. Gold по-прежнему требует одну область ошибки и одну карточку.
6. Явное принятие Review имело отдельный лимит четырёх рамок. Серверное решение теперь подтверждает весь текущий сохранённый набор, без точных геометрических повторов. Само изменение геометрии ничего не подтверждает. Отдельные операции подтверждения `proposed/redrawn` сохраняют прежний предел четырёх областей и проверку причины.
7. При отсутствии локализации выводится «Точное место на листе не определено»; фиктивная рамка или соединитель не создаётся. В PDF текст автоматической карточки получил существующие отступы ручной карточки: номер больше не закрывает начало текста.
8. Обновлены версии кешей автоматического и Reviewed PDF, чтобы ранее построенный PDF не скрывал изменения рендера. Кеши исходных фактов, embeddings и VLM не сбрасываются.

## Границы изменения

Сохранены архитектура сервисов, ACL, серверный источник Review, проверка ревизий, исходные доказательства и вторичные страницы. Действия касаются выбранного `finding_id`. Сохранённые размеры и положение карточки восстанавливаются после изменения состава рамок. Захват в центре верхней границы переносит карточку VLM/Gold целиком без изменения размеров; доступны мышь, стрелки клавиатуры, Escape и Undo. Незавершённое выделение отменяется при Escape, потере захвата указателя, resize и блокировке Review.

N/T/U/D/E/EQ, промпты, нормативный поиск, N-first/T-first, embedding, VLM и Finalization в этом этапе не меняются. Миграции и n8n workflow не изменены; Import → Save → Publish и переиндексация не требуются.

## Проверки

- Frontend: независимые карточки одного объекта, одинаковые bbox разных находок, выбор по ID на нескольких страницах, сохранение исходного payload, добавление/удаление рамок, отмена жеста, восстановление сохранённой геометрии, Undo, редактирование, Gold и итоговый PDF. Эти проверки используют Node и DOM-адаптер; они не заменяют браузерную визуальную приёмку.
- Функциональные HTTP-тесты выполняют настоящие маршруты Gateway → Experience, валидацию, use cases и домен. Проверены переходы `0/1 → 0 → 6 → 2 → 0`, повторное открытие, неизменность оригинала и соседней находки, отсутствие неявного подтверждения, принятие шести рамок. Сеть и PostgreSQL в этом наборе заменены адаптерами.
- Добавлен отдельный PostgreSQL-сценарий сохранения и принятия шести областей в штатном изолированном Experience-наборе. Для фактического выполнения требуется Linux quality gate; локальный пропуск этого набора не является подтверждением SQL-интеграции.
- PDF: настоящий writer, нативные аннотации, отсутствие дублирования, пустая локализация, дробная геометрия и повёрнутые листы. Растровый регрессионный тест сравнивает рендер набора из трёх одинаковых bbox с рендером одного bbox и проверяет отсутствие пересечения текста карточки с номером.

Полный Windows quality gate: **2997 passed, 118 skipped**, Ruff и форматирование прошли. После последующего добавления переноса карточек отдельно повторён весь frontend: **396 passed**, без пропусков. Python после полного прогона не менялся. Пропуски включают наборы, которым нужны изолированные PostgreSQL, Docker и внешние службы; их выполнение не подтверждено. Большие логи сохраняются вне Git в `.codex-test-temp/visual-stage0/`.

## Проверка на реальном PDF и ограничения

Использован доступный локально исходный `777_155-1с-ИОС2.2.pdf`, 31 страница, SHA-256:
`76e3f20c20bd0ab570d04ee93916928c9a56d432045afb3ed5fc46470f49cdfa`.

Построены контрольные PDF до/после на одном исходном документе, с 27 явно тестовыми карточками на страницах 8, 13, 15, 18, 19, 20, 24, 25 и 30. Координаты взяты из нативных слов PDF. Набор включает точные повторы, общую область у двух независимых находок, разнесённые области и отсутствие локализации. Модель и GPU не вызываются. Это технический replay рендера, а не новый анализ документа и не воспроизведение прогонов 8/9.

Переданный пользователем материал помечен `reconstructed_from_annotated_pdf`; видимый номер отчёта нельзя считать исходным `finding_id`. `Square` может быть рамкой карточки, `Line` — прямоугольной границей соединителя. Автоматическое восстановление всех исходных bbox и ручных правок из такого материала некорректно. Последнее сообщение содержит оборванный JSON; локального полного архива с PDF и скриншотами прогонов 8/9 нет.

Подключённый браузер недоступен. Сравнение frontend/PDF по реальным сохранённым результатам двух прогонов, серверный E2E через опубликованный n8n и Linux readiness в этой среде не подтверждены. Этап 0 до этих проверок не считается принятым. Прирост Recall/Precision по H01–H35 не измерен: визуализация сама по себе не доказывает повышение инженерной полноты.

## Ручная приёмка после поставки

1. Открыть сохранённые результаты обоих заданий, проверить страницы 8, 13, 15, 18, 19, 20, 24, 25 и 30. У самостоятельных находок одного объекта должны быть отдельные карточки и номера.
2. Выбрать карточку и затем рамку: подсвечивается только соответствующий `finding_id`, включая его доказательства на других страницах. У соседних замечаний статус и геометрия не меняются.
3. У замечания без области нажать «+ Область», нарисовать рамку, растянуть её и карточку. Удалить рамку, отменить последнее действие. Перезагрузить страницу; сохранённые правки должны восстановиться.
4. Проверить отдельное принятие/отклонение и изменение текста соседних замечаний; добавить и удалить Gold. Проверить роль с `review.findings.decide` без `review.gold.create`.
5. Скачать автоматический PDF; затем принять нужные замечания, утвердить актуальный Review и скачать Reviewed PDF. В автоматическом PDF остаётся исходная визуализация, в Reviewed PDF — принятые замечания и сохранённая геометрия. Проверить номера, области, линии, вторичные страницы и надписи об отсутствии локализации.
6. Повторить при изменённом масштабе и размере окна, после выхода/входа. Незавершённый жест не должен сохранять новую рамку.
