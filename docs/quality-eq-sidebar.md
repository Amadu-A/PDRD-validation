# Достоверность EQ, межстраничный контекст и правая зона PDF

Основание: ТЗ от 2026-11-03; исходный HEAD `4e3c1a5e4a7795b9623c56aa105374c2553a492a`,
ветка `feature/quality`. Один комплект изменений для одного пользовательского коммита.
Агент не выполняет staging, commit, push, deploy или изменение рабочего n8n.

## Причина и исправление

`compare_equipment()` присваивал `needs_review` справочным и неоднозначным фактам.
`compare_equipment_stage()` превращал каждое такое сравнение в отдельное замечание.
Доверие к документу ошибочно заменяло проверку применимости конкретной характеристики.

Теперь сравнение хранит отдельные применимость и причину. Точный паспортный диапазон
по-прежнему даёт совпадение или предметный кандидат; скалярная/текстовая неоднозначность
доказанно относящегося к изделию факта может оставаться вопросом инженеру.
`technical_reference`, недостаточная уверенность, чужая модель/производитель/артикул,
несопоставленные условия и конфликтующие значения сохраняются в диагностике. Все
исходные факты, сравнения, страницы, документы и поисковые попытки остаются в результате.
Неопределённость свойства не становится отдельной претензией на каждую строку справочника.

Одинаковые EQ-вопросы объединяются по физическому обозначению, проектному контексту,
модели/исполнению, свойству, нормализованным величинам, режиму, условиям и документу.
Сохраняются все паспортные страницы, проектные `evidence_locations` и происхождение.
Перед Finalization применяется существующий объединитель с проверкой структурированного
предмета, значений, условий и общего исходного доказательства. Независимые свойства,
расчётные вопросы и режимы не поглощаются. Найденные N/E всех объединённых маршрутов
сохраняются. Повторная Finalization старого справочного EQ-кандидата также проверяет
применимость программно и сохраняет отвергнутый вход в диагностике.

Продолжение конкретного пункта проверяется по соседним страницам до вывода об обрыве
или отсутствии содержания. Сохраняется компактное контрдоказательство со страницами
и цитатами; повторное полное VLM-чтение не добавлено. Для ссылок на таблицы проверяется
производственное/непроизводственное назначение по структурированным полям и исходным
заголовкам подразделов, в том числе если оба подраздела находятся на одном листе.
Имеющаяся проверка нормативной редакции по датированным `status_evidence` не заменяется
найденным текстовым фрагментом; дополнительные ограничения отражены в промпте.

Извлечение фактов и существующие проверочные вопросы уточнены для способов прокладки,
мерзлотных условий, границ сетей, материалов, утечек, баланса, названий схем, выносок,
приложений и нумерации. Это направления проверки по исходным объектам и источникам,
а не встроенные ответы экспертной матрицы. Фактическое повышение полноты требует нового прогона.

## PDF и сохранность Review

Изменён существующий writer Document Service. До расширения сохраняются исходные
визуальные размеры и положения рамок. MediaBox/CropBox расширяются в направлении,
соответствующем визуальному правому краю при 0/90/180/270°. Исходные потоки ограничены
прежним CropBox, чтобы скрытые поля не появились в новой зоне. Исходный масштаб,
нативные объекты, заметки чертежа и координаты error bbox сохраняются.

Карточки находятся только справа: светлая заливка, тонкая красная граница, красный
номер, тёмный текст, отступы 6 pt. Шрифт вычисляется из прежнего фактического размера
до расширения плюс ровно 1,5 pt. Размер не уменьшается при переполнении: добавляются
колонки, а слишком длинная запись получает краткую ссылку на полный отчёт. Каждая
область ошибки сохраняет нативную красную рамку и отдельный Line к своей карточке.
Технические Help-значки и content-tooltip у рамок и линий больше не создаются.
Полные замечания и основания сохраняются в приложении отчёта.

HTML/CSS/JS, Review-контроллеры и сохранённые координаты не изменены. Исходная
пользовательская `callout_box` используется только для определения прежнего размера
шрифта и не перемещается в данных Review. В PDF действует собственная локальная
раскладка. Версии кеша только PDF обновлены до `annotated-v10.pdf` и `reviewed-v4`,
чтобы существующие задания получали новый дизайн без удаления кеша UI-локализации.

Файлы находятся в `.codex-test-temp/pdf-sidebar-preview/`, не включаются в Git.

Матрица `ios2_2_human_remarks_semantic_v2.json` и исходный JSON задания
`ef5894f5-0242-455d-9dfd-3a9cfc7b6585` в доступной рабочей среде не найдены.
SSH `main@192.168.55.3` отклонил ключ этой сессии (`Permission denied (publickey,password)`).
Поэтому новый job_id, реальные число EQ и покрытие 16 аннотаций / 15 вопросов
не измерены. Приведённые в ТЗ 15→99 (84 EQ), 1 matched / 2 partial / 13 not_matched —
исходные данные владельца, не новый результат исправлений.

Для честной оценки добавлен необходимый evaluator `scripts/evaluate_human_remarks.py`.
Он принимает исходную матрицу, реальный API JSON и явные решения рецензента; не оценивает
смысл поиском общих слов. Для положительного решения обязательны существующий finding ID,
реальные страницы, цитата, совпадение предмета/свойства/действия и объяснение.
Поля исходной матрицы, включая `context_used`, `context_pages`, `coords`, сохраняются.
Формат одного решения:

```json
{"hc_id":"HC-01","verdict":"matched","reason":"Объяснение предметного совпадения",
 "matches":[{"finding_id":"реальный ID","pages":[13],"quote":"Дословная цитата реальной находки",
             "object_match":true,"property_match":true,"action_match":true}]}
```

`--decisions` содержит массив таких решений, включая `partial` и `not_matched`.
Для `not_matched` допустим пустой `matches`; при отсутствии оценки скрипт завершается
ошибкой, а не выдумывает метрику. HC-06/HC-07 объединяются только в счётчике уникальных
вопросов, исходные аннотации остаются отдельными:

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_human_remarks.py `
  --matrix .codex-test-temp/ios2_2_human_remarks_semantic_v2.json `
  --result .codex-test-temp/new-result.json --decisions .codex-test-temp/semantic-decisions.json `
  --same-question HC-06,HC-07 --output .codex-test-temp/semantic-report.json
```



## Ручная серверная приёмка

1. Открыть прежнее задание: UI-карточки и рамки остаются на прежних местах. Вход,
   регистрация, добавление Gold, редактирование, изменение обеих областей, принятие,
   отклонение и сохранение после перезагрузки работают как раньше.
2. Скачать оба варианта PDF: карточки только справа, красные рамки на прежних ошибках,
   линия от каждой области ведёт к её карточке; нет Help-popup, наложений и обрезанного
   текста. Проверить кириллицу, номер, полный отчёт и исходные штампы на контрольных листах.
   Открыть в браузере и независимом PDF-просмотрщике; GUI Review не должен сдвинуться.
3. Выполнить новый анализ исходного PDF при тех же настройках N/T/U/D/EQ и версиях
   источников. Сохранить реальный API JSON и job_id. Проверить диагностические EQ-группы,
   сохранность фактов/страниц/источников, отсутствие сравнения разных изделий и режимов,
   продолжение н.1 на 18→19, расход подпитки и назначения таблиц.
4. Составить явную семантическую оценку по матрице и отдельно посчитать 16 аннотаций
   и 15 уникальных вопросов. Сравнить matched/partial/not_matched, ложные срабатывания,
   дубли, подавленные EQ и предметные инженерные вопросы. До этого E2E-приёмка не завершена.
