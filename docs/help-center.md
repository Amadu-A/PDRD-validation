# Встроенная справка и улучшение представления EQ

## Состав и поддержка

Страница `/help.html` доступна без сессии и серверного API. Общая навигация
анализа, личного кабинета и админки добавляет публичную ссылку «Справка».
Оглавление, прямые ссылки, локальный поиск, раскрывающиеся ответы и шесть
сценариев используют существующие ES modules и BEM/CSS entrypoint.
Помощник информационный: не меняет форму и не запускает анализ.

Текст хранится в `frontend/src/js/features/help/content.js`, объяснения реальных
переключателей — в `settings.js`. Та же функция доступности используется
настоящей формой. Markdown — генерируемая копия, проверяемая frontend-тестом:

```powershell
node scripts/export-user-guide.mjs
node scripts/export-user-guide.mjs --check
```

При изменении текста обновите дату, сгенерируйте Markdown и пройдите quality.
Независимые копии объяснений в подсказках не поддерживаются: они используют
тот же источник текста. N/T/U/E не изображаются переключателями; D и EQ
имеют разные значения. Четыре настоящие галочки сохраняют свои значения
и условия доступности. Текст ПЗ также учитывает выключение возможности
конфигурацией.

Таблица EQ имеет постоянную минимальную ширину и прокрутку независимо от
ширины viewport. Читатель может войти в область прокрутки клавишей Tab.
Заголовки столбцов, caption и подпись области доступны вспомогательным средствам.
Размер текста 13 px; статусы не разрываются внутри слов. Лимит объясняется
попытками загрузки, а не вымышленным количеством проверенных паспортов.

Поиск меняется только в Equipment Service: порядок доверенных кандидатов,
консервативный отрицательный отсев и доступность ограниченного продолжения
после пустой выдачи. Миграций, изменения `.env`, алгоритмов N/T/U/D/E и
обновления workflow для этого выпуска нет. Детали приоритетов:
[equipment-chain.md](equipment-chain.md#документ-и-диагностика).

## Windows: проверки и публикация пользователем

Из корня репозитория. Полный вывод в системный временный каталог:

```powershell
$qualityLog = Join-Path $env:TEMP "pdrd-help-quality.log"
& .\ops\check-quality.ps1 *> $qualityLog
$qualityExit = $LASTEXITCODE
Write-Output "quality exit=$qualityExit; log=$qualityLog"
if ($qualityExit -ne 0) { throw "Quality не прошёл. Посмотрите блок ошибки в $qualityLog" }
git diff --check
if ($LASTEXITCODE -ne 0) { throw "Есть ошибки пробелов" }
git status --short
git diff
```

`check-quality.ps1` запускает Ruff, проверку форматирования, весь pytest,
весь Node test suite и Git diff. Если нужно исправление форматирования,
сначала выполните `ops/check-quality.ps1 -Fix` с таким же сохранением лога,
проверьте diff и затем запускайте проверки изменённого кода.

Сверьте явный список изменённых файлов из итогового сообщения с `git status`.
Добавляйте только перечисленные пути, затем просмотрите staged diff.
Коммит и push выполняет пользователь; `origin` настроен на push в оба репозитория.
Перед отправкой проверьте `git remote get-url --push --all origin`.
При ошибке одного push отдельно проверьте, в какой репозиторий коммит уже ушёл.

## Linux: полные тесты и выборочная пересборка

Сервер должен уже находиться на текущей ветке с миграциями предыдущего EQ-этапа.
Не переключайте ветку с незакоммиченными серверными изменениями.

```bash
set -euo pipefail
cd ~/projects/PDRD-validation
git status --short
git branch --show-current
git pull --ff-only

if bash ops/check-quality.sh > /tmp/pdrd-help-quality.log 2>&1; then
    printf 'quality exit=0\n'
else
    result=$?
    printf 'quality exit=%s; log=/tmp/pdrd-help-quality.log\n' "$result"
    tail -n 100 /tmp/pdrd-help-quality.log
    exit "$result"
fi
grep -E 'passed|failed|skipped|Все проверки прошли' /tmp/pdrd-help-quality.log | tail -n 20

docker compose build frontend review-frontend equipment-search-service > /tmp/pdrd-help-build.log 2>&1
docker compose up -d --no-deps frontend review-frontend equipment-search-service > /tmp/pdrd-help-up.log 2>&1
docker compose ps frontend review-frontend equipment-search-service
```

Если отдельный `review-frontend` не запущен и не используется, исключите его
из обеих команд. При запуске действующего Review используйте тот же набор
Compose profiles, что и при его развёртывании. Повторный полный `scripts/up.sh`
для этого выпуска не требуется. Equipment хранит checkpoint при перезапуске;
предпочтительно обновлять между заданиями, чтобы не прерывать внешнюю попытку.
Новые интеграционные тесты выполняются общей Linux quality-командой только
на изолированной БД; рабочая БД и миграции не изменяются тестами.

## HTTPS и загрузка frontend-ресурсов

Проверяйте через тот же внутренний HTTPS-адрес, которым пользуются сотрудники.
Не заменяйте проверку HTTP localhost. Используйте доверенный сертификат;
при необходимости укажите корпоративный CA через `CURL_CA_BUNDLE`, без `-k`.

```bash
origin=https://pdrd.itcneoterm.local
for resource in / /help.html /css/style.css /css/blocks/help-center.css \
    /css/blocks/setting-help.css /css/blocks/equipment-report.css \
    /js/app.js /js/features/help/page.js /js/features/help/controller.js \
    /js/features/help/content.js /js/features/help/settings.js \
    /js/features/help/view.js /js/features/help/context-hints.js \
    /js/features/help/navigation.js /js/features/analysis/equipment-report.js; do
    curl --fail --silent --show-error --max-time 15 \
        -o /dev/null -w '%{http_code} %{content_type} %{url_effective}\n' \
        "$origin$resource"
done
```

Ожидаются HTTP 200, HTML для страниц, JavaScript для JS, `text/css` для CSS.
Также в DevTools → Network проверьте отсутствие 404/5xx, блокировок MIME,
ошибок модулей, смешанного HTTP-контента и незагруженных CSS imports.

## Ручная приёмка

1. Откройте `/help.html` гостем, затем с авторизацией. Справка доступна в обоих
   случаях; главная, кабинет и админка имеют ссылку «Справка».
2. Проверьте прямую ссылку `/help.html#unverified-sources`, поиск «ТЗ»,
   «неподтверждённые источники», пустой результат и сброс. Оглавление и
   возврат назад ведут к нужному разделу, найденные FAQ раскрываются.
3. Переберите шесть сценариев помощника. Меняется только инструкция;
   файлы, выбор раздела, галочки и задания анализа не изменяются.
4. На главной откройте каждую иконку `?`: краткое объяснение и ссылка на
   соответствующую статью. Проверка продолжает запускаться как прежде.
5. PDF: доступны ПЗ/D/EQ, разрешение сайтов только с EQ. CAD: все четыре
   недоступны. PDF + CAD: только ПЗ при включённой возможности. Выключение
   D не выключает EQ/N/T/U; выключение EQ снимает только зависимое разрешение.
6. Запустите анализ с обеими EQ-галочками: разрешение не снимается после
   запуска. При смене файла оно сбрасывается. Неподтверждённый паспорт
   остаётся помеченным; блокировка сайта не обходится.
7. При ширинах 360/768/1440 px и увеличении 200% проверьте читаемость справки,
   формы и таблицы. Длинная таблица прокручивается внутри своего блока;
   страница не расползается, слова и статусы не распадаются на буквы.
8. Клавиатурой Tab/Enter/Space пройдите оглавление, поиск, выбор сценария,
   раскрытие подсказки/FAQ и таблицу. Фокус виден, ловушек фокуса нет.
9. В EQ «Подробнее» различает запросы, попытки загрузки и документы,
   прошедшие проверку применимости. Явно чужая ссылка помечена пропуском
   без расхода загрузки. Подходящая документация всё равно проверяется.
10. Для неполного поиска нажмите «Продолжить проверку»: по умолчанию снова
    до двух попыток нерешённой модели, суммарные счётчики сохраняются.
    Без найденных ссылок продолжение тоже доступно. Лимит числа продолжений
    остаётся ограниченным серверной политикой.
11. Проверьте сохранённые документы, открытие прежней истории и обычный
    Review; разрешённое добавление новых EQ-находок не меняет прежние решения.

Автотесты не заменяют визуальную приёмку через браузер. Реальные 300/500
моделей с внешним поиском и GPU проверяются отдельно по инструкции EQ;
синтетический успешный тест не является подтверждением скорости такого запуска.
