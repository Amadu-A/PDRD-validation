## Общая модель

`domain/engineering_assertion.py` описывает инженерный объект, свойство, тип
претензии, условия, исходные `LocatedDocumentFact` и способ проверки.
Проекция передаётся в существующем `origin_assertions`, включая HTTP между этапами.
Отдельного хранилища и новой архитектуры нет.

План, предметные запросы retrieval, привязка кандидата и финализация используют
одни факты. Модель возвращает тип претензии и ссылки на вопросы плана. Сервер
привязывает эти ссылки к исходным наблюдениям; сами наблюдения модель не переписывает.
В промпте факты передаются один раз, ссылки раскрываются по `fact_id`.
Число нормативных запросов ограничено существующим `max_queries`.

Способы проверки разделены:

- `unverified`: категория и цитата не доказывают вывод; нужен смысловой gate.
- `deterministic`: только однозначная программная проверка одной строки и режима;
  вывод перепроверяется перед обходом финализатора, без вызова VLM.
- `semantic`: межстраничная сопоставимость уже проверена; повторный вызов VLM
  только из-за категории не нужен.
- Недостаточность обоснования сохраняет `needs_review`. Непроверенный резервный
  результат не повышается до подтверждённого нарушения.

Идентичность для объединения: объект + свойство + тип претензии + условия +
пересекающееся исходное доказательство. Сходство свободного текста не используется.
Сохраняются страницы, области, N/T/U/D/EQ, исходные формулировки и происхождение.
Совпадение объекта не объединяет маркировку, спецификацию и вопрос расчёта.

Программное чтение однозначных текстовых строк расходов дополняет факты VLM,
не заменяя их. Обнаруживается различие одного секундного расхода в двух
представлениях; принятие самого расхода требует смысловой проверки условий.
Для табличной проверки соседнее продолжение передаётся полностью, а не только
первые 600 символов. Полный баланс таблицы и достаточность расчёта не объявляются
доказанными одним регулярным выражением.

## Review

- Подключение разрешено при Gold, решениях либо скачивании Review; права действий
  проверяются раздельно. Авторизация не выдаёт дополнительных серверных прав.
- Отчёт, открытый до загрузки сессии, подключается после её получения.
- Первоначальный `open`/`hydrate` можно повторить при пустой очереди. Параллельные
  попытки открытия объединяются, отсоединённый отчёт не получает поздний ответ.
- Повтор команды после ошибки сохраняет прежнюю CAS-ревизию. Конфликт 409
  требует явного восстановления, автоматически не перезаписывает чужие решения.
- Причина ошибки восстановления видна в UI; при удалении контроллера его старые
  обработчики, панели и PDF-кнопка больше не позволяют редактирование.

## PDF и сеть

Автоматический PDF: GET `/api/v1/analyses/{job_id}/annotated-pdf`.
Итоговый PDF: POST `/api/v1/analyses/{job_id}/reviewed-pdf` с текущей ревизией.
Оба адреса относительные, используют текущий origin приложения.

Ошибка DNS возникает до HTTP. Сообщение клиента различает отсутствие HTTP-ответа
и конкретный HTTP-отказ каждого PDF-маршрута; DNS не подменяется ошибкой визуализации.
В среде агента `pdrd.itcneoterm.local` не разрешается (`curl` код 6, HTTP 000).
Пользователь работает через VPN; это не доказывает неисправности серверного DNS.
TLS-проверки не отключались, адреса и секреты окружения не изменялись.

Из Windows с подключённым VPN проверить:

```powershell
Resolve-DnsName pdrd.itcneoterm.local
curl.exe --head --max-time 15 https://pdrd.itcneoterm.local/
```

Если главная страница доступна, сравнить hostname реально неудачного запроса:
он может принадлежать другому ресурсу. Для PDF сохранить HTTP-статус и `detail`
в Network отдельно для каждого маршрута. Cookies и токены в отчёт не включать.

EQ SSE прекращает бесконечные повторы: временные ошибки имеют ограниченные
попытки с задержкой; 401/403/410 завершают подписку сразу. Начальный 404 EQ ещё
может означать, что его задание не создано; разрешено несколько попыток.

Сначала проверить пользовательский путь: открыть старый и новый результат,
добавить Gold, изменить обе рамки, отредактировать, принять/отклонить,

измерять отдельно. Зелёные mock-тесты не подтверждают качество или скорость VLM.
