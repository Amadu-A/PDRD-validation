# Check Norms: объём контекста, отдельная ПЗ и временный HTTP 503

Дата: 22.10.2026. База: `ec621b769735af9562283ebf65899f71562fd6a6`,
ветка `feature/quality`. Подготовка одного коммита пользователя без коммита,
push, развёртывания или публикации workflow со стороны агента.

## Что подтверждено

В присланном Linux-логе общий pytest прошёл: 3090 passed, 117 skipped;
завершены все шесть интеграционных наборов и `STACK CHECK PASSED` /
`PDRD STACK IS READY`. Записи об ограничениях SQL находятся в тестовом контуре
успешно завершившихся проверок; это не traceback сбоя Check Norms нового задания.

На скриншоте Check Norms получает 503 с сообщением о HTTP-ошибке shared-vlm на
`normative_check:4:probe1`. Стадия остановилась при недоступности провайдера,
не при сериализации n8n. Вложенный лог не содержит тела того ответа или журнала
runtime. Точная внутренняя причина исходного 503 не установлена.

Выполненная сейчас проверка без генерации получила HTTP 200 на `/health` и
`/v1/models`; logical alias `shared-vlm` доступен. Это подтверждает текущую
доступность, но не доказывает отсутствие временного сбоя ранее.
SSH не дал прочитать runtime-журнал по доступному ключу; дополнительных выводов
или путей у пользователя не запрашивалось. Модель, GPU и shared infrastructure
не изменялись.

Прежнее исправление Runner сохраняется: Code-узлы PDF не получают растры,
геометрию и всю историю выполнения. Оставались повторные длинные тексты источников,
смешение ПЗ с native-текстом и отсутствие повтора страницы после исчерпания
коротких HTTP-попыток адаптера.

## Изменения

1. PDF-пакет использует обратимый `text-pool-v1`: повторная строка передаётся один
   раз, а её позиции — отдельными ссылками. Восстановление выполняется до проверки
   `CheckNormsStageRequest`. Полные N/T/U/D, факты, геометрия, SHA, нормативные
   поля, строки условий и исключений остаются на прикладном пути без изменений.
   Нет смыслового отбора, нового top-k или обрезания текста ради размера.
2. Native-текст и ПЗ разделены. PDF и PDF+CAD раньше передавали в Check Norms
   `analysis_text` с приписанной ПЗ. Программное извлечение могло ошибочно считать
   этот текст содержимым текущей физической страницы. Теперь используются
   исходный `page.text` и отдельные `project_context_sources` с собственными
   страницами. CAD получает ту же явную ПЗ, которая раньше использовалась главным
   образом при построении поисковых запросов. Текстовые фрагменты ПЗ не сокращаются
   до прежнего поля `text_excerpt`; они берутся из `project_context_texts`.
3. В представлении фактов/гипотез/D для модели исключены пустые атрибуты и лишние
   JSON-пробелы. Непустые значения, нули, координаты и условия сохраняются. В промпте
   прямо указано: опущенный атрибут неизвестен и не доказывает отсутствие элемента.
   Полные исходные объекты для программных проверок и provenance не меняются.
4. После коротких попыток адаптера временные HTTP 408/425/429/500/502/503/504
   допускают ограниченный повтор **сбойной страницы**. Успешные страницы пакета
   не повторяются. Ожидание ограничено, учитывает `Retry-After` и проверяет отмену.
   Слот общей модели на ожидании стадии освобождён. Неверный контекст и известные
   ошибки запроса не повторяются этим механизмом. Обычная программная ошибка не
   заменяется пустым результатом.
5. В ошибке порта сохраняются HTTP-статус, безопасный код провайдера и Retry-After.
   В логе видны длина промпта, размер HTTP-запроса, request ID и код отказа без
   исходного текста проекта. Плохой запрос провайдера в Check Norms возвращается
   как HTTP 502; временная недоступность — HTTP 503. Тело ошибки провайдера с
   возможными цитатами документа не публикуется.
6. Метаданные `metrics.stage_retry` сохраняют ожидание и известные затраты
   неуспешных попыток. Неизвестный token usage остаётся неизвестным, а не нулевым.

Новые настройки application, уже внесённые в `.env.example`:

```dotenv
ANALYSIS_SERVICE_PIPELINE__VLM_STAGE_TRANSIENT_RETRIES=2
ANALYSIS_SERVICE_PIPELINE__VLM_STAGE_RETRY_DELAY_SECONDS=5
```

Это два дополнительных повтора страницы после внутренних попыток адаптера,
с ожиданием по умолчанию 5 и 10 секунд. Retry-After ограничен 60 секундами.
Число параллельных запросов, параметры модели, embedding и схема N-first не менялись.
Постоянно недоступный runtime по-прежнему остановит анализ с явной ошибкой.

## Проверки и измерения

До исправления регрессии воспроизвели отклонение упакованного запроса и остановку
31-страничной стадии после одного временного 503. После исправления проверены:

- Точное восстановление строк и отсутствие мутации исходного запроса.
- Недопустимые ссылки отвергаются до обращения к модели.
- Реальный ASGI HTTP Check Norms с 31 страницей, N/T/U/D/ПЗ и временным отказом
  четвёртой страницы: HTTP 200, все 31 страницы по порядку, только страница 4
  выполняется два раза. Источники, полный конец ПЗ и её страница 16 доступны модели.
- Постоянный 503 остаётся ошибкой после трёх попыток страницы; HTTP 400 не повторяется.
- Отмена во время ожидания не запускает новый запрос модели и возвращает штатную отмену.
- Retry-After учитывается; ошибка сохраняет безопасный код и метрики без текста проекта.
- Настоящий JavaScript из PDF workflow исполняется в Node VM; восстановленные
  N/T/U/D/ПЗ и исходные данные побитово эквивалентны по JSON-значениям.
- Настоящие HTTP-выражения CAD и PDF+CAD сохраняют ПЗ отдельно от native-текста.

Синтетический 31-страничный тест повторных цитат: **2 439 634 → 48 032 байта**,
с точным восстановлением исходного содержимого. Это измерение тестового JSON,
не сохранённого production-payload размером 7,5 МБ со скриншота.
Оно не является замером скорости или инженерной точности VLM.

Первый общий Windows gate: 3105 passed, 118 skipped; 398 frontend-тестов,
Ruff, зависимости и `git diff --check` прошли. После добавления проверок двух
соседних workflow итог повторного gate записан в локальный комплект
`.codex-test-temp/context-503-fix/quality-verified.log`.
Итоговый gate прошёл: **3107 passed, 118 skipped**, 398 frontend-тестов,
Ruff check/format, проверка зависимостей и `git diff --check` — успешно.
Полный pytest занял 127,82 секунды; новые мок-сценарии не обращаются к GPU.

Linux gate и readiness из вложения относятся к предыдущему коммиту. Исправленный
production-проход с реальным ТЗ, всеми чекбоксами и shared-vlm ещё не выполнялся.
Промпты изменились, поэтому точный VLM-кэш первого нового прогона может быть холодным.
Прошлые benchmark-замечания не выдаются за результат нового E2E.

## Поставка

Исходники, тесты и документация подготовлены одним набором. Полный список для
staging находится в `.codex-test-temp/context-503-fix/staging-paths.txt`, полные
тексты — в `full-source.md`, архив — в `context-503-fix-sources.zip` рядом с ним.
PDF, логи, диагностические снимки и архив не добавляются в Git.
Миграции и переиндексация нормативной базы не требуются. Production frontend,
Review, его геометрия и PDF-рендер не менялись; изменён только frontend-тест workflow.

Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\check-quality.ps1 -Fix
if ($LASTEXITCODE -ne 0) { throw "Quality gate не пройден" }
git diff --check
git diff --stat
git add --pathspec-from-file=.codex-test-temp/context-503-fix/staging-paths.txt
git diff --cached --check
if ($LASTEXITCODE -ne 0) { throw "Проверьте staged diff" }
git diff --cached --stat
git commit -m "fix(analysis): compact context and recover transient VLM failures"
if ($LASTEXITCODE -eq 0) { git push origin feature/quality }
```

На сервере:

```bash
cd ~/projects/PDRD-validation
git pull --ff-only origin feature/quality &&
bash ops/check-quality.sh > /tmp/pdrd-context-quality.log 2>&1 &&
bash scripts/up.sh > /tmp/pdrd-context-up.log 2>&1 &&

```

- `n8n/workflows/analysis-v2-pdf-cad.json`;

webhook-путями создавать не требуется. Старый несжатый контракт поддерживается,
но упаковка и разделение ПЗ заработают после публикации обновлённого workflow.
