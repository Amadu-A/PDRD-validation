# Версии Experience и ручная индексация

## Назначение

Страница `/experience.html` работает с постоянным каталогом на основном frontend
`http://192.168.55.3:8080`. Инженер выбирает замечания и явно создаёт версию.
Добавление, редактирование и утверждение замечания сами по себе не запускают embedding.
Этот документ дополняет [каталог](experience-catalog.md) и [поиск E](experience-index.md).

Сейчас реализованы каталог версий, ручная очередь векторизации, фиксированный
состав наборов для дообучения, ZIP выбранной версии и приём отчёта качества
векторной версии. Серверное назначение проверенной версии подключено к поиску
Knowledge по нормативному разделу. Фактическое обучение, регистрация проверенных
весов и переключение общего VLM требуют отдельного этапа. Рабочий поиск E
остаётся выключенным до независимой оценки и приёмки.

Жизненный цикл обучения, размеры весов, предлагаемое хранилище и зависимость
от будущих пользователей: [experience-model-lifecycle.md](experience-model-lifecycle.md).

## Работа с таблицей

- Таблица использует компактный шрифт, миниатюры и кнопки с иконками.
- Отдельные колонки показывают раздел нормативного документа, автора и дату создания.
- Чекбоксы сохраняют выбор между страницами. «Очистить выбор» снимает отметки.
- «Выбрать все» обходит все страницы по текущим фильтрам; предел одного набора — 1000 записей.
- «Удалить выбранное» отправляет один запрос с ID и редакциями. Сервер удаляет
  весь набор одной транзакцией; конфликт любой строки отменяет всё удаление.
- Значок удаления в строке использует тот же сценарий для одного замечания.
- Удаление логическое: запись исчезает из списка и обучения, история остаётся.
  Повторное утверждение того же примера не отменяет удаление.

Удаление из каталога не изменяет уже утверждённый PDF и операционный Human Review.
В Review красный крестик означает решение `rejected`; это отдельное действие.

## Раздел нормативного документа

`section_id` — UUID раздела, по которому сервер искал нормативные подтверждения
в управляемой базе Knowledge. `section_title` — его название из этой базы.
Gateway берёт UUID из сохранённого `normative_snapshot` задания или артефактов
и получает название через порт нормативного каталога. Experience переносит оба
поля в источник и редакцию. Ссылка на документ/пункт остаётся отдельным полем
`normative_reference`; свободный текст замечания для угадывания раздела не используется.

Новым записям раздел назначается автоматически. Перед ручным созданием версии
`RefreshCatalogSources` дополняет старые записи из доверенного источника анализа:
сохраняет их UUID, ручные правки, удаление, исходные тексты и историю; восстановление
отмечается новой редакцией с CAS. В том числе восстанавливается первоначальная
область старого Bad. Если историческое задание не содержит раздела, сервер сообщает
причину исключения, не просит вводить технический идентификатор в форме запуска.

Одна версия содержит один нормативный раздел. Сервер исключает текстовые,
неактивные и неоднозначные примеры и возвращает список ID с причинами; пригодная
часть выбора создаёт версию. Если пригодных примеров нет, задача не создаётся.
Несколько разделов подготавливаются отдельными версиями.

## Просмотр версии и её состав

Слева от «Выгрузить замечания» расположены вид артефакта, базовая модель и версия.
Одновременно просматривается один вид: векторная база или набор/модель дообучения.
Переключение этих списков **не применяет** версию к рабочему анализу и не меняет
чекбоксы. Отметки сохраняются также при переходе между видами артефактов.

Выбор версии устанавливает фильтр её нормативного раздела. Зелёный фон отмечает
замечания из сохранённого состава. Если редакция примера изменилась, строка
показывает, что версия содержит прежнюю редакцию.
«Выбрать отсутствующие в версии» выбирает по фильтрам новые записи и изменённые
редакции, которые ещё не входят в выбранный состав. Создание новой версии
фиксирует именно отмеченные строки; предыдущая версия не расширяется автоматически.

Версию можно переименовать без изменения состава, модели и коллекции.
Удалённая версия исчезает из селекторов. Строящуюся и применённую версию удалить нельзя.

Над таблицей постоянно доступны два отдельных действия для выбранных чекбоксами
замечаний: «Запустить индексацию выбранных замечаний» и «Подготовить набор для
дообучения». Тип создаваемой версии задаётся нажатой кнопкой и не зависит от
режима просмотра. Диалог объясняет, создаётся коллекция Qdrant либо набор данных.
Оба действия сохраняют выбор строк; при пустом выборе кнопки недоступны.

Для просматриваемой версии отдельный блок показывает сборку, допуск качества,
причину недоступности назначения и ошибку worker. Эти сведения остаются видимыми
после обычного обновления таблицы. Статус «готова» у векторной базы относится
к успешному построению коллекции, а не к подтверждённому улучшению анализа.
Снимки и аудит сохраняются; физическая очистка Qdrant и PNG сейчас не выполняется.
Она потребует отдельного сценария с проверкой ссылок и действующих версий.

Кнопка «Выгрузить замечания» сохраняет прежнее назначение: экспортирует текущий
отфильтрованный каталог в ZIP. Отдельная кнопка «Выгрузить фиксированный набор
версии» отдаёт сохранённые редакции выбранной версии и изображения независимо
от текущих фильтров и последующих правок каталога. Формат и проверки архива:
[experience-dataset-export.md](experience-dataset-export.md). Это не экспорт
бинарных весов.

## Ручная векторная версия

1. При необходимости уточнить причину отказа Edited + Rejected; раздел назначает сервер.
2. Отметить замечания: сервер проверит актуальность, активность, принятую область
   либо исходную область VLM для Bad, PNG и однозначное назначение обучения.
3. Выбрать «Векторные базы», нажать «Запуск индексации выбранных замечаний».
4. Задать имя версии и базовую модель. Для штатного worker используется
   `shared-embedding`; другая модель требует совместимого worker и своей identity.
5. Версия появится в очереди. После обработки нажать «Обновить» для просмотра статуса.

| Состояние | Значение |
|---|---|
| `queued` | Ручное задание сохранено, worker ещё не забрал его |
| `building` | Worker держит аренду и строит отдельную коллекцию |
| `ready` | Весь выбранный состав успешно проверен и записан |
| `failed` | Построение не завершено; причина показана в реестре |
| `prepared` | Зафиксирован набор для дообучения, готовых весов ещё нет |

Сбойные версии не публикуются как готовые. После устранения причины создаётся новая
версия из актуальных выбранных примеров. Остановка worker оставляет аренду на
10 минут; после истечения задание забирает другой worker. Heartbeat продлевает
аренду. Старый владелец не может завершить задание нового владельца.

Knowledge опрашивает **очередь заданий**, обычно раз в 30 секунд, и не обходит
автоматически весь каталог. При пустой очереди embedding и Qdrant не вызываются.
До и после GPU-запросов проверяются редакции, fingerprint и актуальность источников.
Коллекция имеет серверное имя `pdrd_e_<embedding_identity>_<version_uuid_without_hyphens>`.
Браузер не задаёт путь, коллекцию, identity или статус готовности.

## Наборы дообучения

Отдельная кнопка «Подготовить набор для дообучения» подготавливает выбранные замечания.
Сохраняются базовая модель, полный состав редакций, тексты, назначения, ссылки
на PNG и SHA-256 manifest. Версия получает `prepared`, а поле `weights_sha256`
остаётся пустым. Переименование, подсветка и выбор отсутствующих работают
так же, как для векторной версии.

ZIP фиксированной версии уже можно выгрузить для будущего эксперимента; он не
задаёт формат конкретного тренера. Для дальнейшего обучения потребуются разделение
training/held-out по SHA документов, воспроизводимые параметры обучения,
хранилище весов и регистрация контрольных сумм. Edited + Rejected допускается
только после явного уточнения причины и объекта отрицательной оценки.
Подготовленный набор не обозначается как готовая дообученная модель.

## Применённые рабочие версии

Отдельный блок под заголовком предназначен для подтверждённых рабочих версий.
При успешном применении селектор получает зелёный фон и эффект утопленной
кассеты с переходом около секунды; предпочтение уменьшенного движения учитывается.
Просмотр таблицы не меняет сохранённые назначения `applied_artifacts`.

Сервер требует `ready` и `quality_approved`; для VLM также требуется SHA-256 весов.
UI повторяет эту проверку, в том числе запрещает назначать набор без весов.
Worker может изменить только аренду и результат индексации, не качество.
Для готовой векторной версии инженер может загрузить JSON-отчёт независимой
оценки. Experience проверяет точную привязку к составу, индексу и параметрам,
заявленное непересечение SHA документов оценки с составом и пороговые метрики.
Исходный парный эксперимент и подлинность PDF подтверждает инженер. Отчёт с
неуспешными метриками сохраняется без допуска; ошибочный отчёт отклоняется.
Отдельная кнопка отзывает допуск. Оба действия используют текущую редакцию
версии, сохраняют аудит и снимают её прежнее рабочее назначение.

После положительного допуска назначение готовой векторной версии сохраняется
в `applied_artifacts` для её нормативного раздела. При включённом рабочем E
Knowledge читает это назначение и ищет только в выбранной коллекции; отсутствие
раздела либо назначенной версии не запускает embedding. Сохранённое назначение
само по себе не включает `KNOWLEDGE_SERVICE_SEARCH__EXPERIENCE_ENABLED`.
Сейчас независимого проверочного набора нет: новые версии не получили реальный
допуск, рабочий E выключен, а использование маршрута на Linux не принято.
Управление загрузкой общего VLM и применение обученных весов не подключены.

## Bad и повторные прогоны

После завершения всех решений кнопка итогового Human Review PDF сохраняет все
финальные решения пакетно. Bad получает неизменные первоначальные `proposed_regions`
и crop VLM без отдельного подтверждения. Правки инженера лежат отдельно в
`display_regions`. При отсутствии исходных координат Bad сохраняется текстовым.
Он исключён из обучения; PNG/рамка не придумываются. Accepted без области и
отклонённый Gold также остаются в каталоге, но не допускаются к обучению.
Undo до утверждения учитывается по текущему состоянию Review; Pending в итоговый
каталог не попадает.

Операционный Review сохраняется по мере действий для восстановления после
перезагрузки. Материализация каталога запускается при утверждении PDF: это разные
операции. Ошибка crop/SQL не отменяет утверждение; повтор скачивания завершает перенос.
Внутри SQL перенос всего набора атомарен. HTTP-вызовы и запись PNG не входят в SQL-транзакцию.

Дедупликация использует SHA-256 оригинального PDF, лист, происхождение, тег,
решение, исходный/текущий тексты и основания, исходные/текущие области.
Пробельные различия текста нормализуются; координаты округляются до шести знаков.
ID задания, ревизия Review, время, автор, заполнение раздела и размещение
карточки не создают новый пример. Перемещение назад в исходную область
не создаёт дополнительный геометрический дубль.
Новый текст, область или решение создают новый пример. Равный пример сохраняет
правки/удаление каталога и получает дополнительное происхождение в `catalog_occurrences`.
Источник актуален, пока хотя бы одно из соответствующих утверждений актуально.

## Таблицы и ответственность

Все SQL-таблицы находятся в собственной схеме `experience`:

| Таблица | Назначение |
|---|---|
| `catalog_occurrences` | Связь одного примера с утверждениями повторных прогонов |
| `artifact_versions` | Имя, модель, раздел, состояние, manifest и аренда |
| `artifact_members` | Фиксированные редакции примеров и их fingerprint |
| `artifact_events` | Аудит создания, переименования, удаления и результатов |
| `applied_artifacts` | Назначение рабочей версии по виду и нормативному разделу |

Experience владеет отбором, реестром и метаданными; Knowledge владеет embedding
и Qdrant. Document Service вырезает PNG из оригинального PDF. Gateway проверяет
серверный actor и задания **всего выбранного набора до записи**. Будущая политика
прав остаётся заменяемым портом; система пользователей сейчас не добавляется.

Индексный ключ разрешает чтение пригодных проекций/PNG и ограниченные операции
claim/heartbeat/result. Он не разрешает изменять Review, каталог, метрики качества
или рабочие назначения. Ключ Review не принимается индексным каналом.

## Миграция и запуск

Миграции `20260929_0004` и `20260929_0005` сохраняют старые JSON/crop/редакции, заполняют content key
и происхождение существующих записей. Старые дубли не удаляются автоматически;
новые прогоны сопоставляются с самой ранней записью. Рабочая миграция выполняется
online через штатный Alembic; offline SQL допускает только пустой каталог.
Downgrade 0005 возвращает прежний ключ; downgrade 0004 удаляет реестр/происхождение.
Для обычного обновления откат миграций не нужен.

Windows — общие проверки, коммит и push в `origin`; отдельный приватный remote
`neoterm` отправляется следующей командой:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\check-quality.ps1 -CommitMessage "fix: validate Experience applied versions and workflows" -Push
git push neoterm feature/experience-base
```

Linux — получить ветку из настроенного приватного upstream и обновить сервисы:

```bash
cd ~/projects/PDRD-validation || exit 1
git switch feature/experience-base &&
git pull --ff-only &&
bash ops/deploy-experience-index.sh </dev/null
```

Скрипт сначала останавливает прежний автоматический индексатор, выполняет общие
и изолированные PostgreSQL-тесты, применяет миграции и запускает ручную очередь.
Volumes/старые коллекции сохраняются. Shared-сервисы не изменяются.
В `b1ba688` изменены три n8n workflows (`analysis-v2-pdf.json`,
`analysis-v2-cad.json`, `analysis-v2-pdf-cad.json`): они передают `section_id`
в запрос E и привязывают ответы к `finding_id`. После обновления кода инженер
вручную загружает их в n8n и нажимает
Publish; проектный deploy-скрипт публикацию workflows не выполняет.
Linux runtime-проверка новой версии требует запуск кнопкой на реальных данных;
Windows HTTP-тесты используют тестовые embedding/Qdrant порты.

Проверочный поиск по ID готовой версии из селектора:

```bash
docker compose --profile review --profile experience-index exec -T experience-indexer \
  python -m pdrd_knowledge_service.experience_runtime preview --version VERSION_UUID "Маркировка извещателя"
```

`preview` и `evaluate --version VERSION_UUID /tmp/evaluation.json` привязаны к
фиксированному составу, модели, identity и разделу версии. В отчёт оценки входят
version ID и manifest SHA; рабочие назначения и флаг E эти команды не меняют.
