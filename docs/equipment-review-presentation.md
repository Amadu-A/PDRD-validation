# Таблица оборудования, список замечаний и большой нормативный ответ

## Таблица EQ

Пять столбцов: № п/п, полное наименование, физические листы PDF,
проверенный сайт производителя, использованный документ.
Техническая диагностика открывается отдельно кнопкой «Подробности проверки».

Все позиции specification.structured_items отображаются по item_id,
включая разные позиции одной модели. Поиск и документ остаются общими для модели;
построчные сравнения выбираются по позиции и странице. Вхождения обычных
чертежей также сохраняются. Без структурированной спецификации остаётся
отображение прежнего массива моделей или инвентаризации.

Окно таблицы содержит не более десяти реальных строк. Внутренний скролл
перемещает окно; служебные строки сохраняют общую высоту. Высота десяти позиций
измеряется после переноса текста и изменения ширины. Диагностика находится
за пределами окна. Заголовок закреплён; на телефоне доступен горизонтальный скролл.

Документ показывается как прочитанный только при сохранённом source_id.
Кнопка snapshot использует прежний авторизованный Gateway-маршрут.
Редакция, доверие, URL и SHA остаются доступны. Сохранение документа само по себе
не означает соответствия характеристик; неоднозначная редакция требует уточнения.

manufacturer_site необязателен. Resolver выдаёт его только для включённого
подтверждённого официального домена реестра, сопоставленного с производителем
и итоговым URL уже проверенного документа. Дилерский URL не становится сайтом
производителя. Неизвестный производитель не дополняется догадкой.

Явные метаданные relationship=analog отображаются с обязательным пояснением.
Analysis исключает такой документ из сравнения проектного изделия и генерации
EQ-нарушения. Автоматический подбор аналога этим изменением не вводится.

Разрешение неподтверждённых источников допускает pending-документ в текущем
задании с unverified_user_override; пометка сохраняется в snapshot, фактах,
основаниях и интерфейсе. Заблокированные и выключенные домены запрещены.
Существующие SSRF, TLS, redirect, формат и размеры загрузчика сохраняются.

## Замечания и Review

Четыре фильтра соединяются через И. Подтверждение системой и решение инженера
хранятся отдельно. Список не меняет категорию, серьёзность, исходный текст или
источники. Сортировка стабильна; начальный порядок отдаёт приоритет pending,
серьёзности и странице. Узлы карточек перемещаются, а не создаются заново.

Используются прежние ReviewController, очередь и HTTP-команды. Отклонённая
запись остаётся в текстовом списке, но исключается из листа и итогового PDF.
Gold сохраняет своё происхождение. Гипотезы видны для чтения и не добавляются
в серверный Review. Компактная история поступает из настоящего аудита Experience.

Переход использует прежний renderer, ждёт изображение и на 2,5 секунды
подсвечивает область по finding_id. При отсутствии геометрии сообщает об этом.
Для позиции оборудования временная рамка строится только по её сохранённым
координатам. Ошибка изображения не выдаётся за успешную локализацию.

## Переполнение Check Norms

Прежний bulk-ответ мог просить слишком много замечаний за один вызов, хотя
бюджет 14000 токенов оставался ограниченным. Теперь ёмкость порции — до десяти,
а общий max_issues и правила классификации остаются прежними.

Полная порция продолжается с уже найденными кандидатами. Сохранённые N/T/U/D
источники и общий контекст страницы передаются в каждую порцию. При типизированном
исчерпании ответа следующая схема уменьшается 10 → 5 → 2 → 1; prompt, schema
и stage меняются. Обрезанный JSON не принимается. Неудача единичной порции остаётся
явной ошибкой. Сетевые ошибки не маскируются как повод уменьшать порцию.

Полный JSON с finish_reason=length сохраняется, но не считается доказательством
завершения проверки; выполняется меньшая порция. Отмена перед продолжением
использует существующий progress probe и возвращает analysis_cancelled.
Слепые повторы того же budget в n8n не включаются.

## Приёмка

- Unit: порции, сохранение кандидатов/источников, budget failure, остановка и отмена.
- HTTP-интеграция: настоящий vLLM-adapter с контролируемой сетевой границей;
  обрезанный ответ, 10/10/5, сохранённые находки, HTTP 409 при отмене.
- Функциональные: pending/blocked/disabled, реальный PDF, production извлечение
  характеристик и сравнение, сохранение доверия, отсутствие нарушения по аналогу.
- Review HTTP: настоящий сценарий решений, CAS, восстановление, компактная история
  и отсутствие доступа без служебного ключа и актора.
- Frontend: пять столбцов, позиции спецификации, 11/300/500 строк, фильтры,
  все сортировки, решение/правка/восстановление, реальные контролы, безопасные URL,
  ожидание изображения, адресная подсветка и отсутствие координат.
- Браузер: Chrome 1440×1000 и 390×844, 500 синтетических позиций, десять строк DOM,
  достижение конца, 20 шагов скролла, Review, переходы, без ошибок JavaScript.

Реальная GPU-проверка страницы 22 ИОС 4.1.7 выполнена с кешем, выключенным
на время приёмки: HTTP 200, пять порций, 35 итоговых замечаний, без output-budget
ошибок. В этом прогоне внешние N/T/U/D источники отсутствовали. Исходный Input
упавшего Check Norms с нормативным контекстом нужен для точного повторения сбоя.
scripts/check_normative_vlm.py --input ... --page 22 принимает такой экспорт
и сохраняет полные входы, ответы и метрики во временный каталог.

Проверки 300/500 позиций подтверждают интерфейс и ограниченные сценарии тестов.
Работа 500 моделей с внешним поиском и GPU требует отдельной серверной приёмки.
Изменения не требуют миграций, новых переменных .env или импорта workflow n8n.
